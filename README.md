## 更新日志

**2026-11-24（安卓每日任务"卡在大世界不动"的根因修复）**

- **根因：安卓端"是否在大世界"永远判不出来**。PC 端用右上角队伍栏的 `1/2/3` 数字徽章（`char_1_text`/`char_2_text`/`char_3_text`）判定，但**安卓客户端的队伍栏是圆形角色头像，根本没有数字徽章**——这三个模板在安卓大世界画面上的匹配置信度只有 **0.11~0.15**（阈值 0.8），永远匹配不上。于是 `in_team()` 恒为 False → `is_main()` 恒为 False → `ensure_main()` 一路等到 **600 秒超时**（日志里 `wait main esc=True` → 恰好 601 秒后报"请在大世界并在队伍中开始"）。期间只有 `wait_login` 一条日志来回刷，看起来就是"卡住不动、不跳过、也没额外日志"。
- **修复**：新增 `src/task/android_world.py`，安卓端改用**与角色/场景无关的 HUD 元素**判定大世界——左上角小地图雷达里的**黄色玩家箭头**（实测 339~502 个黄色像素，登录页/加载页/活动页均为 0）、底部偏左的**协奏金球**（534~717），并用"右上队伍栏白条 + 底部血条"做兜底组合。PC/云游戏判定逻辑一行未改。
- **顺带修掉一个假阳性**：加载界面底部有一条**贯穿全屏的白色加载进度条**（实测单行连续白像素 1299），位置和血条重叠，只看"白像素总数"会把加载界面误判成大世界（2240 ≥ 2200）。现在按"连续白像素长度"区分（加载页 1313 vs 大世界 93），加载界面会被明确排除。
- **新增可观测性**：以前三个模板全落空时**完全静默**，现在会打出每个模板的实际置信度；安卓端还会打印 `in_team(android): in world (radar_yellow=347)` / `not in world (...)`，黑帧单独告警，排查不再瞎猜。
- **MuMu 抓屏黑帧不再静默卡死**（`ok/device/capture_methods/nemu_ipc.py`）：MuMu 的 IPC 通道偶尔会"返回成功但画面全黑"（实测 `mean=0`，错误截图也是纯黑，等于没有任何现场信息）。现在全黑帧会**重建 IPC 连接重试 3 次**，仍失败就抛带明确中文原因的异常（不再是一个空 message 的裸 `Exception`），并提示"确认模拟器窗口可见、未开启后台保活"。
- **新增安卓端"连接已断开"弹窗处理**（`src/task/BaseWWTask.py` 的 `handle_android_disconnect`）：MuMu 挂机久了或网络抖动会弹【连接已断开】对话框，此时**画面背后仍然是���世界**，`in_team` 判定依然为 True，任务以为一切正常，但所有点击都被弹窗挡住——表现和用户反馈的"卡住不动"完全一样。现在先用廉价亮度预筛（中央亮像素占比 ≥ 0.5，实测弹窗 0.78、其余 ≤ 0.11）确认有大弹窗，再 OCR 确认文案（实测 `连接已断开` / `确认` 置信度均为 1.0），点掉"确认"并复位登录态，交给既有的 `wait_login` 重新登录。
- **实测验证**：在 MuMu 15.0 上真实走通"连接页 → 点击连接 → 加载 → 大世界"，新判据对 **大世界 / 加载界面 / 活动页 / 登录页 / 全黑帧** 共 10 张带标注真实帧全部判对；断线弹窗处理 5/5 通过（真实调用 `onnxocr` 走完整决策链）。

**2026-11-24（MuMu 模拟器窗口化操作：像 PC 客户端一样输入）**

- **模拟器输入改为 PC 键盘/鼠标消息**：以前 adb 设备固定用 `input keyevent`/`input tap`——这是直接给安卓系统发按键，**绕过了 MuMu 的键位映射**，导致 esc 变成安卓返回键、主界面弹出"退出游戏"、键位表完全没被用上。现在（`config.py` + `ok/device/DeviceManager.py`）：模拟器的截图与输入都走 Windows 窗口通道（`capture_method: windows` + `interaction: PostMessage`），与 PC 客户端/云游戏完全一致——发真实键盘/鼠标消息给 MuMu 窗口，由模拟器自己的键位映射转成游戏操作。顺带修复了 `MouseResetTask` 在 adb 下刷 `get_abs_cords` 报错的问题（PC 截图类本有该方法）。

**2026-11-24（安卓触屏专用操作模式）**

- **安卓键位/操作抽成独立模式层**（`src/task/touch_mode.py`）：以前"打开菜单"和"返回/关闭"两种语义都压在 `esc` 上，触屏下又被全局映射成 `KEYCODE_BACK`，导致 MuMu 里 `wait main` 一直触发返回、打不开菜单（实测主界面发 `KEYCODE_BACK` 弹的是"是否确定退出游戏"）。现把触屏操作集中到一个模式层：安卓端「返回=打开菜单」是同一个按钮，按你给的键位表用 `` ` ``（菜单/跳过 → `KEYCODE_GRAVE`）；指南书用 `F2`。PC/云游戏行为完全不变（仍走各自的 `esc`）。`is_main`、`open_esc_menu`、`openF2Book` 已改走该入口。
- **补全触屏功能键**：`ADB_KEY_MAP` 增加 `F1-F12` → `KEYCODE_F1..F12`，指南书 `F2` 在触屏下才是合法按键。

**2026-11-24（MCP 端口自适应）**

## 本地安卓模拟器（ADB）

除了 Windows 客户端和云浏览器，ok-ww 现在也支持本地安卓模拟器 / 真机，通过 ADB 连接。设备选择列表会自动列出已安装的模拟器与已连接的 ADB 设备。

**游戏包名**：国服 `com.kurogame.mingchao`、国际服 `com.kurogame.wutheringwaves`，脚本按实际安装情况自动识别并拉到前台，两者都装了也没问题。

**准备工作**：

1. 若首次使用报缺少 `adbutils`，在 ok-ww 安装目录执行 `python -m pip install adbutils`（`adb.exe` 由该包自带，无需单独安装 Android SDK）。
2. 真机需在「开发者选项」里打开 USB 调试；无线设备先用 `adb connect <IP>:<端口>` 连上（MuMu 等模拟器一般会自动连接，无需手动操作）。

**在 ok-ww 里连接**：

1. 启动模拟器 / 真机并装好鸣潮。
2. 打开 ok-ww，在设备选择里找到对应设备（如 `MuMuPlayer-15.0-0`、`127.0.0.1:16384`），点开连接设置：
   - **MuMu 12**：捕获方式选 `Ipc`（`Nemu Ipc Capture`，模拟器原生截图通道，速度快，推荐）——脚本会自动识别已安装的 MuMu 12 实例并给出该选项；
   - 其他模拟器 / 真机：保持 `ADB`（通用 `adb screencap`，后台可用但约 3fps / 300ms 每帧）。
3. 多开模拟器时每个实例是独立设备，按序列号分别选择即可，互不干扰。
4. 之后按普通设备运行任务。

**注意**：ADB 设备是独立设备入口，不套用云浏览器（云鸣潮）的专用逻辑；通用 ADB 通道约 3fps，适合日常 / 回合类内容，实时战斗循环（如精细变轴）建议用 MuMu IPC 通道，并自行实测效果。

### 安卓端常见问题

**「每日任务进入大世界以后一直卡在那不动，也不跳过也没其他操作也没额外日志」**

这是 2026-11-24 之前的老问题，根因与修法见上面更新日志的「安卓每日任务"卡在大世界不动"的根因修复」。升级后日志里会出现这几条，可以直接对照判断卡在哪一步：

| 日志关键字 | 含义 |
| --- | --- |
| `in_team(android): in world (radar_yellow=...)` | 已在大世界，判定通过 |
| `in_team(android): not in world (...)` | 不在大世界，后面会列出四个判据的实测数值 |
| `安卓端截图全黑(MuMu 抓屏失败)` | MuMu 抓到了空帧，不是"不在大世界" |
| `Game disconnected, closing the notice and logging in again` | 命中了【连接已断开】弹窗，正在重新登录 |
| `MuMu 模拟器抓屏持续返回空画面(全黑)` | 抓屏通道真的坏了，需检查模拟器窗口是否可见、是否开启「后台保活」 |

**MuMu 抓屏偶尔返回全黑画面**：模拟器窗口被最小化/遮挡、或 MuMu 设置里开了「后台保活」时，IPC 通道会返回一张纯黑图。现在脚本会先自动重建连接重试，仍失败会明确报错，不会再"卡住不动"。

**停在【连接已断开】对话框**：挂机过久或网络抖动导致。脚本会自动点"确认"并重新登录；也可以手动把游戏切回大世界再启动任务。

## 更新被官方覆盖后怎么恢复

ok-ww 自带更新会还原 `working` 和 `repo` 中的文件。两种恢复方式：

- **直接覆盖**（同版本文件被还原）：关闭 ok-ww 后双击 `一键恢复.bat`，或命令行 `python restore.py`。恢复前会自动备份当前文件。
- **重新打补丁**（大版本升级后结构变化）：按上面"安装"步骤运行 `install_to_local_app.py`。

两种都不会动账号 Cookie 和任务配置。详见 [`docs/backup-and-restore.md`](docs/backup-and-restore.md)。
