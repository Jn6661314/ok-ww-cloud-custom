# v1.8.9 · 修复云鸣潮战斗中途误判脱战、敌人没打完就停 / Fix cloud combat stopping mid-fight

本版改了运行时代码，**必须重跑 `python restore.py` 并重启 ok-ww** 才生效。

## 问题

云鸣潮有时会「打着打着敌人没打完就莫名其妙停了」。日志里的固定路径是：

```
BaseCombatTask:combat check not in combat
BaseCombatTask:combat_once out of combat break combat check not in combat
TacetTask:开始走向奖励
TacetTask:进入战斗，控物状态：None
TacetTask:Tacet reward is unavailable and combat is still active. Resuming in the same arena.
```

脚本先把还在战斗的目标判成脱战、退出战斗循环去走奖励；`walk_to_treasure()` 30 秒超时后
官方才发现「战斗其实还没结束」，又重新打一遍。中间那段就是用户看到的「停了」。

## 根因

官方对云游戏是**锁定图标优先 + 血条辅助**的双判定：`has_target()` 用锁定图标金色像素，
没锁定时看 `check_health_bar()`，血条刚消失还有 `CLOUD_HEALTH_LOST_GRACE = 3` 秒宽限。
官方**没有** `no_enemy_for()` 这种硬窗口。

我们定制后来加的 `no_enemy_for()` 为防血条闪烁无限续命，对所有端统一用
`NO_ENEMY_EXIT_SECONDS = 2` 秒——**比官方 3 秒宽限还短**。云游戏串流延迟、技能特效遮挡
会让锁定图标和血条同时闪断 2~3 秒，宽限还没到期就被判「没有敌人」，`reset_to_false()`
把战斗打断。

## 修复

`src/combat/CombatCheck.py`：

1. 新增 `CLOUD_NO_ENEMY_EXIT_SECONDS = 6.0`，`no_enemy_for()` 按端分流：PC 2 秒、
   安卓 4 秒、云游戏 6 秒（仍大于官方 3 秒宽限，且 6 秒后仍能正常收尾，不会无限续命）；
   聚落任务继续用自己配置的锁敌超时，不受影响。
2. 新增 `CLOUD_RETARGET_HEALTH_LOST = 3`，重锁时血条闪断的提前放弃阈值云游戏从 1.2 秒
   放宽到 3 秒，PC/安卓仍是 1.2 秒。
3. 判定仍以官方的锁定图标 + 血条双信号为准，没有引入新的识别方式。
