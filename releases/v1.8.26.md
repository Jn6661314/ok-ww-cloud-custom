# v1.8.26 — 手机投屏：按键变触点（可校准的键位映射）+ 电脑上能看到手机画面

两件事，都是投屏真正当"设备"用起来的最后一步。

## 一、为什么 MuMu 上能按、投屏上不能

MuMu 上脚本发 `send_key('e')` 是能生效的，但**那不是 ok-ww 的功劳**：是模拟器自带的
**键位映射**把真实键盘事件翻译成了那个位置的屏幕触摸。

真机没有这一层。查了 NectarLink 手机端的实现：

```kotlin
// PhonePlatform.kt:295
if (!Elevated.handle(input)) InputService.handle(input)

// Elevated.kt:1139
is MirrorInputEvent.Key -> keys[event.key]?.let { "K $it" }   // 注入 Android 按键事件
```

也就是说 PC 发过来的 `e`，到手机上只是一个 **Android 按键事件**。而鸣潮手游只认
**触点** —— 按键事件它根本不处理。协议层也没有任何消息能改对端的键位映射
（`phone.toggles` 只管免打扰、铃声这些）。

**结论：这层映射只能由 ok-ww 自己做。** 那就把 MuMu 里配过的那份映射，搬到 ok-ww 自己身上。

## 二、具体做了什么

### 1. 键位映射表：键 → 屏幕比例坐标

新增 `src/phone_mirror_keymap.py`，一张表：

```json
{ "`": [0.045, 0.065], "1": [0.96, 0.30], "e": [0.80, 0.65] }
```

坐标是**屏幕比例（0..1）**，和横竖屏、缩放、黑边都无关 —— 和投屏触控协议本身一致。
表存在 `configs/phone_mirror_keymap.json`，可以手改。

### 2. 交互层：命中映射就发触点

`PhoneMirrorInteraction.send_key()` 现在先查表：

- 查到 → `TOUCH_DOWN` → 停一下 → `TOUCH_UP`（就是"在那个位置按一下"）；
- 查不到 → 才退回手机按键事件（`back`/`home`/`enter` 这类系统键）。

### 3. 返回/菜单这个老问题

手游里 **返回和打开菜单是同一个按钮**，而且是屏幕左上角那个 —— 发 `esc` 过去，
手机收到的是 `KEYCODE_BACK`，鸣潮的反应是**弹"是否确定退出游戏"**，不是返回。

所以让投屏也算「触屏」（`TouchMode.is_touch`）：`back()` / `open_menu()` 改走键位表的
`` ` ``，由上面那张表翻译成左上角的一次点击。

**默认值只给了它**（位置固定），其余键留空：

> 技能、切人这些按钮的位置随手机分辨率、刘海、游戏里的自定义布局而变，
> 硬编码一套"标准布局"大概率点偏 —— 点偏比不点更糟（技能点成闪避）。

### 4. 「校准键位」：点一下就会

配置 → 手机投屏 → **校准键位(点屏幕)**：左边列出 9 个键（菜单/返回、切人 1/2/3、
技能 E、共鸣解放 R、交互 F、跳跃、锁敌 Y），选中一个，在右边**投屏画面上点它对应的按钮**，
坐标就记下来了，自动跳到下一个。点完按保存，之后和 MuMu 上一样。

实测（真机画面）：点两下 → `{"`": [0.93, 0.31], "1": [0.96, 0.30]}`，写盘正确。

## 三、电脑上显示手机画面

内置引擎的设备是个"伪设备"（没有窗口），所以以前屏幕上什么都看不见，任务卡住
只能猜。新增**预览窗口**：

- **独立连一条**到投屏内核的连接。内核的 `serve` 是循环 `accept`、每个连接单独推流，
  所以它**不会抢任务那条连接**（这一点专门看过实现才敢这么做）；
- 实时显示画面，可缩放，默认窗口置顶，底部显示真实分辨率（如 `864x1920`）；
- 入口两个：
  - 配置 → 手机投屏 → **预览手机画面**（内核没跑会自动拉起来）；
  - 配置项 **运行时显示画面**（默认开）：任务启动时自动弹出。

实测：窗口正常出画面（截到手机当前界面 `491x1080`），置顶勾选有效。

## 四、验证

- 新增 12 项测试（`tests/TestPhoneMirrorKeymap.py`）：
  - 默认表里「菜单/返回」一定存在（这条不通整条任务链都卡住）；
  - `esc`/`escape` 指向同一个按钮；
  - 校准值覆盖默认值、别名只落一份、超出 0..1 的坐标被丢弃；
  - 文件损坏时退回默认表；
  - **映射过的键发的是触点而不是按键事件**（这版的核心）；
  - 没映射的键才回退手机按键；
  - 投屏被识别为触屏（`back()` 发的是 `` ` `` 不是 `esc`）。
- Python 全量 **477 项通过**；
- 校准窗口、预览窗口都用**真实内核**开过、截过图；`restore.py` 自检 45 个文件两处一致。

## 五、你需要做的

1. 重跑 `python restore.py`，重启 ok-ww；
2. 手机**横屏进游戏**（重要：竖屏画面里点出来的坐标对横屏游戏无效）；
3. 配置 → 手机投屏 → **校准键位(点屏幕)** → 把「切人 1/2/3」「技能 E」「共鸣解放 R」
   这些点一遍 → 保存；
4. 之后任务就能像在 MuMu 上一样按键了，返回/菜单也不用再手点。

## 说明

按约定本版**不做实机验证**：已验证到的是「映射表读写、按键翻译成触点、两个窗口能开能显示」，
「点下去游戏里真的响应」由使用者确认。

若校准后某个键仍然没反应，多半是那个键在任务里发的名字不在表里 —— 把
`working/logs/ok-script.log` 里的 `手机投屏: 键位 ... -> ...` 和那一刻的日志发我，
我把它补进校准列表。
