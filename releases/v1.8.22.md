# v1.8.22 — 修好配对二维码（之前根本没码，手机也扫不出来）

v1.8.20 把内置投屏内核做出来了，但第一次真机使用就卡在配对这一步：
配对窗口能打开，状态栏写着「等待手机扫码…」，**二维码那块却是一片空白**，
手机自然扫不了。

## 问题出在哪

日志里内核其实一切正常——配对链接已经拿到了：

```
21:48:11 投屏内核已启动(... --pair)
21:48:11 手机投屏: 等待手机扫码配对
```

所以问题不在内核，在 ok-ww 把链接画成二维码这一段。**三个 bug 叠在一起**，
每一个单独都足以让二维码出不来。

### 1. 转成 Qt 图像时 bytesPerLine 算错了（界面全白的直接原因）

```python
QImage(image.data, width, height, width, QImage.Format_BGR888)
```

`bytesPerLine` 是**每行的字节数**，而 BGR 每个像素 3 字节，所以必须是
`width * 3`。写成 `width` 之后，Qt 认为每行的数据不够 1/3，直接给出
**空图**——界面上就成了一块白板，连二维码的影子都没有。

实测（OpenCV 5 + PySide6 6.11）：

```
bytesPerLine=width    -> isNull: True   size: (0, 0)
bytesPerLine=width*3  -> isNull: False  size: (366, 366)
```

### 2. 二维码被反相了（就算显示出来，手机也扫不动）

OpenCV 的编码器输出的**本来就是标准极性**（深色模块 = 0、浅色模块 = 255，
也就是白底黑码）。之前那段 `np.where(matrix > 0, 0, 255)` 把它反相成了
黑底白码——而绝大多数手机扫码器只认白底黑码。

拿真实配对链接（178 字符）生成两张图对比，左边是原样、右边是反相：

| 原样（OpenCV 输出） | 反相 |
| --- | --- |
| 白底黑码，三个角有定位图案 | 黑底白码，手机扫不动 |

之前那条测试断言的恰恰是反相后的样子，等于把错误当成了标准。

### 3. 少了静区（quiet zone）

编码器只画模块本身，不画四周的空白。标准要求四周留 4 个模块宽的静区，
少了它，定位图案贴边，手机在屏幕上扫容易失败。

## 改了什么

### ok-ww 侧（`src/phone_mirror_pairing.py`）

- `qr_image()` 不再反相，直接用编码器的原始输出；
- 补上 4 个模块宽的静区；
- 缩放从 8 倍改成 6 倍：真实配对链接 178 字符 → 53×53 模块，
  加上静区共 61×61，6 倍是 366 像素，正好落在窗口里不裁切；
- 新增 `_to_pixmap()`：`bytesPerLine` 用 `width * 3`，并在转换前用
  `np.ascontiguousarray` 保证行是连续的；Qt 给出空图时会记警告，
  而不是默默显示一块白板。

### ok-ww 侧（`src/phone_mirror_engine.py`）

内核的状态走 stdout，正常是每行一个 JSON。但内核也会往 stdout 写别的东西，
那样会把后面的 JSON 粘在同一行，整行就不合法了——**一条消息就这么被吞掉**。
所以解析器现在除了试整行，还会按大括号配平把 JSON 对象逐个抠出来。

### 内核侧（`core/nectarlink-sidecar/src/main.rs`）

配对时要问「手机上显示的码是不是这个」，这个提示原本用 `print!` 写 stdout，
而且没有换行——它会粘在下一条 JSON 前面，把那条消息毁掉（`paired` 尤其致命，
配对成功了 ok-ww 却不知道）。改成写 stderr，stdout 保持纯 JSON。

顺带把配对码的切分从按字节改成按字符（`&code[..3]` → `char_indices().nth(3)`），
虽然现在是 6 位数字不会出问题，但按字节切非 ASCII 字符串会 panic。

## 验证

- **端到端**：拿内核真实发出的 178 字符配对链接（`nectarlink://pair?v=0&id=…&a=…`，
  含 URL 编码的 `%3A`/`%2C`），走完「编码 → 加静区 → 缩放 → 转 Qt 位图 →
  从位图读回 → 扫码」整条链，扫出来**与原文逐字符相同**；
- 用新二进制实跑一遍配对：stdout 只有 1 行、纯 JSON、无污染，
  配对链接 178 字符正确拿到；
- 眼见为实：把窗口实际显示的位图存成图片核对过 —— 白底黑码、
  三个角定位图案齐全、四周有静区；
- 新增 11 项测试（二维码可扫回原文、极性、静区、Qt 转换不为空、
  stdout 噪声容错等），全量 **437 项通过**。

## 你需要做的

**重跑 `python restore.py` 并重启 ok-ww**（这版换了内核二进制，
必须重新部署）。然后配置 →「手机投屏」→「配对手机(扫码)」，
这次应该能看到二维码了。

## 说明

按约定本版不做实机验证：二维码的**生成与显示**这一环已经端到端验证过
（从窗口实际显示的位图里能扫回原文），但「手机扫码 → 授权 → 出画面 →
点击落到手机」这条链仍由使用者确认。
