# v1.8.28 · 修好投屏配对没二维码 / 任务启动报错 / Win10 云游戏闪退，附解压即用成品包 / Fix pairing, task startup and Win10 cloud crash, with a ready-to-run build

本版是 v1.8.27 之后的一批修复，**三处代码问题 + 一次文档精简**。成品包按这版重新打包。

已部署到运行目录并跑过全量测试（236 项通过）。仓库方式需重跑 `python restore.py` 并重启

## 一、投屏配对一直「正在启动中」、没有二维码

配对时会先看上次的内核端口还在不在，在就**直接复用**。但那个残留内核不是配对模式启动的，
不会输出配对消息，而且它的 stdout 管道属于上一个 ok-ww 进程——新进程读不到状态，于是
配对窗口永远停在「正在启动中」，二维码出不来。校准窗口连到这个旧会话，看到的还是旧画面。

现在配对模式**强制清掉残留内核再起新的**，不再复用；清理逻辑也从 `link.json` 读准确 pid
（Windows 上残留进程的命令行常是空的，只按命令行匹配会漏掉它）。

> 这次连不上还叠加了一个手机端因素：手机 NectarLink 里这台电脑显示离线（内核日志里
> `port: 0`），在手机上点「重连」并允许后才连上。PC 侧代码没问题；手机端的操作按老规矩
> 仍需你在实机上确认。

## 二、任务启动直接报错（v3.8.18 的两个新方法缺失）

官方 v3.8.18 给 `DeviceManager` 加了 `uses_child_session()` / `child_session_client()`，
框架的 `start_controller` 和子会话页都会调用。我们的定制版是基于旧版打的补丁，缺这两个方法，
任务一启动就抛 `AttributeError`，状态栏每两秒刷一次错误。

现在照官方实现补回这两个方法，并让 `uses_child_session()` 在**手机投屏 / 云游戏 / MuMu**
下返回 `False`，避免误进子会话分支。

## 三、Win10 云游戏 1080p 一打开就闪退

`config.py` 里云游戏 viewport 默认 `(1920, 1080)`，Chromium WebRTC 抓这个尺寸在 Win10 上会崩。
已改为 `(1600, 900)`——官方 `supported_resolution` 列明的 16:9 档位，识别按帧宽高等比缩放照常。

只改了 `browser`，PC 子会话（`child_session`）仍是 1920×1080，手机投屏是另一条抓屏链，都不受影响。
browser 配置没有单独的 JSON 覆盖，改动对所有用户生效，不需要迁移。

## English summary

Three fixes after v1.8.27, plus a documentation cleanup.

**1. Pairing stuck at "starting" with no QR code.** The engine startup reused a live port from a
previous run, but that leftover engine was not started in pairing mode, so it never emitted the
pairing message and its stdout belonged to the previous ok-ww process. Pairing now always kills
stale engines first and reads the exact PID from `link.json` (Windows command lines are often empty
for those processes). A separate phone-side factor was also involved: the phone showed the PC as
offline and only connected after "reconnect" was tapped there — that part still needs your
on-device confirmation.

**2. Task startup crashed.** Official v3.8.18 added `uses_child_session()` / `child_session_client()`
to `DeviceManager`; our patched version lacked them, so `AttributeError` was raised on every start.
Both methods are restored, with `uses_child_session()` returning `False` for phone mirroring, cloud
gaming and MuMu.

**3. Win10 cloud gaming crashed at 1080p.** The browser viewport default is now 1600x900 instead of
1920x1080 — a supported 16:9 resolution that avoids the Chromium WebRTC crash. Only `browser`
changed; `child_session` stays 1920x1080 and phone mirroring uses a different capture path.

**4. Docs.** README's per-version changelog was compressed into a short table (all entries verified
present in `CHANGES.md`); the agent install prompt was trimmed from 148 to 88 lines while keeping
all actionable steps.

236 tests pass. No in-game verification was done for this release, by prior agreement.
