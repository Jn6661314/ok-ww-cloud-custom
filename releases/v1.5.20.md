# v1.5.20 · 拉海洛方块"越跑越卡最后冻死"根因修复

## 问题

无尽模式运行一段时间后整机变得很卡, 随后任务完全不动, 日志零输出, 只能手动暂停/重启。v1.5.19 的 15 秒 CDP 超时修复上线后依然复现 (18:57:28 与 19:02:13 两次, 分别静默 100 秒与 51 秒)。

## 根因 (关机线程转储实锤)

ok-ww 关机时会写线程转储 (`logs/shutdown_thread_dumps.txt`), 其中 TaskExecutor 线程定格在:

```
_play_board → choose_move (rahai_blocks.py:238)
  → clear_lines → board_value (rahai_blocks.py:220 genexpr)
```

**走棋搜索组合爆炸, 与浏览器/捕获无关**:

- 无尽模式托盘是 **4 块** 布局 (`TRAY_LAYOUTS` 第三项, 现场日志出现 slot=4);
- `choose_move` 的束宽保护写死了 `len(batch) == 3` (普通模式托盘), 4 块走 `else` 分支后**中间状态不裁剪**;
- 深度 2 起状态数指数膨胀: 单次 `choose_move` 要评估**上千万次** `clear_lines + board_value`, 纯 CPU 单核跑满数分钟 —— 既表现为"很卡很卡"(整机被拖慢), 又表现为"不动了"(搜索没结束, 零日志因为卡在纯计算里);
- 放完一块就开始下一步搜索, 所以两次冻结都紧跟着 slot 落块日志。

顺带发现: `src/task/rahai_blocks.py` 此前**不在 restore.py 部署清单**, 本次修复前运行目录里一直是旧副本 —— 已补入清单并重新部署。

## 修复

1. **束搜索裁剪改为任意托盘大小生效**: 除最后一层外全部裁剪 (每剩余子集最多 24 状态 + 全局束宽上限 96), 3 块托盘行为与旧版完全一致;
2. **墙钟兜底**: 单次 `choose_move` 预算 3 秒, 超时直接采用已找到的最优解返回 —— 无论盘面/托盘什么状态都不可能再卡死;
3. `rahai_blocks.py` 补入部署清单, 三处哈希校验一致。

## 效果

- 4 块托盘搜索: 卡死数分钟 → **0.9 秒内** (新增回归测试断言 < 5s);
- 墙钟预算耗尽场景: 立即返回最优解 (新增测试把预算调到 1ns 验证);
- Rahai 全部测试套件通过。
