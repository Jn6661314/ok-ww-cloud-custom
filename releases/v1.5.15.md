# v1.5.15 · 爱弥斯轮转修复: 变奏入场必出招 / Aemeath rotation fix: always perform on intro

## 中文

### 问题
爱弥斯(Aemeath)在场上的表现为"切了也不放技能": 日志显示她每次被切上场后
**0.3~0.9 秒内立即被切走**, 技能动作日志(普攻/强化E/大招)恒为 0 次, 与队友
Denia(SubDps)↔Verina(Healer) 形成每 2.7 秒的切人死循环
(`support_buffs_active_return_to_main_dps` ↔ `unbuffed_subdps`)。

### 根因(上游 ok-ww 原版 Aemeath.py 的设计缺陷)
上游逻辑: 队里有副C时, 爱弥斯只在"变奏入场 + **两个队友都满协奏退场且 buff
未超时**"(has_all_buff)才出招, 否则站场待机立即切人。

实测该条件几乎永远不成立:
- `last_buff_time` 只在角色**满协奏退场**时打点(switch_out 里 switched_with_full_con);
- 副C Denia 的轮转经常在协奏未满时就被切走(切走瞬间读数 0.0), 她的 buff
  永远不成立 → `has_all_buff` 恒 False → 爱弥斯永远走待机分支。

### 修复
定制 `src/char/Aemeath.py`(已加入 restore.py 部署清单):
- **变奏入场(has_intro)就正常输出** —— 强化E/大招/二段大仍由模板判定
  (`aemeath_e1/e2`、`aemeath_lib2`)兜底, 不会乱放;
- 满 buff + 入场时保留上游 `must_cast_lib2_this_turn` 强制二段大逻辑;
- 未入场且队里有副C时保持上游待机行为(不抢站场), 无副C队保持站场输出。

### 验证
- 新增 `tests/TestAemeathRotation.py`(8 项: waits_for_intro 规则 ×3、
  do_perform 四分支 ×4、required_action_pending ×1)全部通过;
- 11 个安卓/云回归套件全部 OK;
- `restore.py` 部署 working + repo, `Aemeath.py` 三处哈希一致。

## English

### Problem
Aemeath "switches in but never casts": logs show she was switched out again
**0.3~0.9s after entering**, with zero skill-action logs (attack/enhance-E/liberation),
forming a 2.7s switch ping-pong with Denia(SubDps)↔Verina(Healer)
(`support_buffs_active_return_to_main_dps` ↔ `unbuffed_subdps`).

### Root cause (upstream Aemeath.py design flaw)
Upstream logic: with a sub-dps in team, Aemeath only performs when
"intro entry + **both teammates exited at full concerto within their buff windows**"
(has_all_buff); otherwise she stands by and immediately switches out.

In practice this is almost never true:
- `last_buff_time` is stamped only when a char exits **at full concerto**;
- Sub-dps Denia is routinely switched out before her concerto fills
  (reads 0.0 at exit), so her buff never validates → has_all_buff always False
  → Aemeath always takes the standby branch.

### Fix
Custom `src/char/Aemeath.py` (added to restore.py deploy manifest):
- **Perform normally on every intro entry (has_intro)** — enhance-E /
  liberation / lib2 are still gated by template detection
  (`aemeath_e1/e2`, `aemeath_lib2`), so nothing is spammed;
- Keep upstream `must_cast_lib2_this_turn` forced-lib2 logic for
  all-buff + intro;
- Keep upstream standby behavior when no intro and a sub-dps exists;
  keep on-field behavior when no sub-dps in team.

### Verification
- New `tests/TestAemeathRotation.py` (8 tests) all green;
- All 11 android/cloud regression suites OK;
- Deployed via `restore.py`; `Aemeath.py` hashes identical across
  custom/working/repo.
