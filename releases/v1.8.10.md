# v1.8.10 · 修复首次进配置页不显示账号按钮 + MuMu 设备列表加载慢 / Fix account buttons on first config open + slow MuMu device list

本版改了运行时代码，**必须重跑 `python restore.py` 并重启 ok-ww** 才生效。

## 一、首次进入多账号配置页不显示「保存登录状态 / 切换账号」按钮 / Fix: buttons missing on first open

### 问题

云鸣潮（设备选「云游戏」）下，刚打开 ok-ww 就直接进多账号任务的设置页时，
**「保存登录状态」「切换账号」两个按钮不出现**；等一会儿再进页面才出现。表现像按钮"丢失"了，
容易让人以为没装好补丁。

### 根因

按钮的显隐由 `_is_cloud_device()` 决定，它走的是这条判定链：

```
is_browser() → get_preferred_device() → device_dict
```

而 `device_dict` 依赖设备管理器的**异步刷新**——应用刚启动、还没扫完设备时，
`get_preferred_device()` 拿不到结果，按钮判定就落空了。

### 修复

`_is_cloud_device()` 加"配置已存在"兜底：设备列表尚未就绪（`get_preferred_device()` 返回 None）时，
回退检查 `browser_config` 是否存在——只要云游戏配置已声明，就按云设备处理，按钮照常显示。
设备列表就绪后的判定逻辑不变，PC / 安卓设备下按钮仍然不显示。

## 二、MuMu / 设备列表加载很慢 / Fix: slow device list caused by bridge fallback sweep

### 问题

打补丁后打开设备下拉要卡好几秒才出列表，MuMu 模拟器场景尤其明显。

### 根因

`DeviceManager` 的 MuMu 网桥回退逻辑（`adb_connect_bridge_fallback`）在常规发现失败时，
会解析 `arp -a` 输出并对**整个 ARP 表的每个 IP** 逐个探测 5555 / 16384 端口，
单次探测超时 0.4 秒——ARP 条目多时一次回退就要十几秒，而且**每次刷新设备列表都重扫一遍**，
结果完全不缓存。

### 修复

`ok/device/DeviceManager.py`：

1. 新增 `BRIDGE_FALLBACK_TTL = 120` 秒的结果缓存（`self._bridge_cache`）：同一 IP+端口的
   成功/失败探测结果 2 分钟内直接复用，不再重复探测；
2. 单次探测超时 0.4 秒 → 0.25 秒，进一步压缩最坏情况。

首次探测成本不变（该兜底只在上桥失败时触发），后续刷新设备列表从十几秒降到毫秒级。
