# v1.8.18 · 修复 MuMu 战斗切人永远只切 1 号位 / Fix MuMu combat switching always on slot 1

本版改了运行时代码，**必须重跑 `python restore.py` 并重启 ok-ww** 才生效。

## 现象

MuMu（手游模拟器）战斗时切人一直在 1 号位打转，切不到 2 号位；日志里角色身份每 0.1~0.2 秒就变一次：

```
info_set Chars 渊武, 奥古斯塔
info_set Chars 漂泊者, 奥古斯塔
info_set Chars 折枝, 奥古斯塔
info_set Chars 漂泊者, 莫特斐   ...（213 次）
```

## 根因

这是一条**识别抖动 → 切人失效**的连锁反应：

1. 手填编队为空（`"MuMu 编队": ""`），安卓端走**画面识别**队伍栏头像。
2. 原投票锁定 `android_vote_team_identity` 要求**连续 3 次识别一致**才锁定编队。战斗特效/伤害数字干扰头像识别，每次读到的组合都不同（渊武/折枝/漂泊者/奥古斯塔/莫特斐 乱串），连续一致永远达不到 —— 日志里「编队锁定」**0 次**，从未锁定。
3. 没锁定 → `load_chars()` 每帧重新识别 → 角色身份和 `index` 每帧变化 → 脚本维护的当前下标 `_android_current_index` 被反复重置为 0（1 号位）。
4. `android_switch_key()` 按当前下标推导 1/2 切人键，下标恒为 0 → 切人目标映射全乱 → **永远停在 1 号位**。

## 修复

### 1. 战斗中首次识别即锁定（根治抖动）

- 战斗中（`in_combat` 为 True 或未知）：**首次拿到有效识别就立即锁定编队身份**，之后整场战斗**绝不换锁**——即使某帧识别乱串或读空。
- 非战斗（选队/大世界）：保留原"连续 3 次一致才锁"逻辑，避免换队瞬间误锁。
- 锁定后 `load_chars` 用固定 identity 构建角色，不再每帧重建，角色身份/index/`_android_current_index` 全部稳定 → 切人 1/2 键映射正确。

### 2. 手填编队改为下拉点选（防写错角色名）

- 「MuMu 安卓 Config」新增三个下拉：`MuMu 编队角色1/2/3`，选项为全部官方角色名（58 个），**点选即可，不会写错**，槽位顺序固定。
- 读取优先级：三个下拉槽位 > 旧的逗号分隔字符串（老配置继续可用）。
- 某个槽位写了无法识别的名字会**跳过该槽位**并告警，不再让整个编队作废。
- 想精确控制编队（尤其换队后立刻生效）就填这三个下拉；留空则走自动识别 + 首次锁定。

## 你需要做的

1. 重跑 `python restore.py`，重启 ok-ww。
2. **推荐**：到「MuMu 安卓 Config」用三个「编队角色」下拉按你的实际队伍点选角色（1 号位/2 号位/3 号位），这样最稳、换队立即生效、完全不依赖画面识别。
3. 若不想填：留空即可，本版会在战斗开始首次识别后自动锁定编队（换队后需重进战斗才重新锁定）。
4. 确认键位映射里切人键仍是 1/2 两颗（对应编队两个非出战队友）。
