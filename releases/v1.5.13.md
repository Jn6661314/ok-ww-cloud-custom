# v1.5.13 · 安卓编队锁定 + 协奏环（延奏）识别修复 / Android formation lock + concerto ring (outro) fix

发布日期 / Date: 2026-11-25

## 问题 / Problem

- **中文**：
  1. MuMu 延奏识别失效，切人也不对：经常一个角色 A 到死，不切奶妈。
  2. 战斗逻辑混乱：频繁 "target lost try retarget" 后提前退出战斗。
- **English**:
  1. On MuMu the outro (concerto-full) detection never triggers and character switching is wrong — one character attacks to death and the healer never rotates in.
  2. Combat logic is erratic: frequent "target lost try retarget" then early exits.

## 根因 / Root Cause

### 角色识别抖动（切人/奶妈全乱的主因）

- **中文**：手游右上角队伍栏是**圆形头像**（直径约 110px@1920x1080），PC 端头像约 64px——大了约 1.7 倍，而且手游头像是"整个头部"构图，PC 模板是"脸部特写"裁剪。上游 `load_chars` 直接用 PC 的 `box_char_1/2/3` 框 + 头像模板做固定尺度匹配，框位错位 + 尺度错配 → **同一支队伍 2 秒内读出 4 种组合**（实时日志：`漂泊者,漂泊者,渊武` → `渊武,渊武,仇远` → `渊武,漂泊者,仇远` → `渊武,渊武,绯雪`）。角色的 MainDps/SubDps/Healer 类型随之每帧漂移，切人优先级、奶妈切换、角色连招代码全部失效——表现就是"一个人 A 到死、不切奶妈"。
- **English**: The mobile party bar uses circular portraits (~110px) with full-head framing while the PC templates are tight face crops (~64px). The upstream `load_chars` matches PC-scaled templates in PC-positioned boxes, so the same team read 4 different rosters within 2 seconds; char types (MainDps/SubDps/Healer) drifted every frame, breaking switch priorities and healer rotation.

### 协奏环（延奏）检测失效

- **中文**：手游元素图标（血条左侧金色星形）中心实测 (0.388, 0.917)@1920x1080，直径约 70px（PC 约 50px）。协奏弧贴在图标外沿（半径约 37~42px），而 PC 协奏检测框 `(1431,1942)-(1557,2068)@3840` 的环带半径只有 22~27px@1920——**在手游上完全扫不到弧**。实测日志 `current_con` 恒为 0/0.0，`has_intro` 永远 False，延奏机制（含协奏满触发的切人优先级）从不生效。
- **English**: The mobile element icon is bigger than PC's, so the concerto arc sits at radius ~37–42px while the PC detection box annulus only scans 22–27px — the arc is never found, `current_con` stays 0, `has_intro` never becomes True.

## 修复 / Fix

`config.py` + `src/char/CharFactory.py` + `src/task/BaseWWTask.py` + `src/task/BaseCombatTask.py`，PC / 云游戏行为不变。

### 中文

1. **安卓编队锁定（编队为准的三层实现）**：
   - **第 1 层（推荐）**：全局设置新增 "MuMu/安卓 Config" → "MuMu 编队" 配置项，直接手填编队角色名（按槽位顺序，支持中文/英文，如 `绯雪,漂泊者·衍射,渊武` 或 `Hiyuki,Rover,Yuanwu`）。填了就是唯一事实来源，**完全不做画面识别**；
   - **第 2 层（自动）**：把右上角队伍栏区域裁剪后缩放 0.58 倍到 PC 头像尺度再匹配（阈值 0.72，低于阈值记未知槽位）。缩放结果贴回与主帧同尺寸的黑画布，避免触发 `FeatureSet.check_size` 清空特征缓存；
   - **第 3 层（锁定）**：连续 3 次识别一致才锁定编队；锁定后 `load_chars` 完全跳过画面识别，偶发误读无法撼动锁定；非战斗时每 15 秒复检一次，用户换队自动重锁（自恢复），**战斗期间绝不复检**；
   - 全部失败时退回上游 PC 框模板识别老路径，保证战斗不中断。
2. **安卓协奏环检测框标定**：新增 `ANDROID_CON_BOX` (1385,1875,1595,2085)@3840x2160，框高 210px → 环带半径 36.9~44.4px@1920，恰好覆盖手游协奏弧（37~42px），且元素图标本体（半径约 35px）整体落在环带内孔里不会误判；PC/云检测框保持原样。
3. **`android_team_size()` 修正**：编队锁定/手填编队优先，其次按已加载角色数——修掉"角色未加载时默认 3 人队→第三槽读到垃圾→垃圾永远参与轮转"的正反馈死循环。
4. **`android_switch_key` 直接受益**：锁定后槽位确定，1/2 键映射推导不再受识别抖动影响。

### English

1. **Android formation lock (3 layers)**: (1) a new global config "MuMu 编队" lets the user type the formation directly (Chinese or English names, slot order) — when set, zero on-screen recognition; (2) otherwise the party bar is cropped, scaled 0.58x to PC avatar scale (threshold 0.72) and matched on a canvas the same size as the main frame so `FeatureSet.check_size` doesn't wipe the feature cache; (3) the team locks after 3 consecutive consistent reads and `load_chars` then skips recognition entirely; rechecks only run out of combat every 15s so a team change re-locks automatically; falls back to the upstream PC-box path when all else fails.
2. **Android concerto box calibration**: a dedicated bigger box centered on the mobile element icon; its annulus (36.9–44.4px @1920) covers the mobile concerto arc while the icon itself stays inside the hole. PC/cloud box unchanged.
3. **`android_team_size()` fix**: locked/configured team size first, then loaded-char count — removing the feedback loop where an unloaded roster defaulted to 3 and a garbage third slot kept participating in rotation forever.
