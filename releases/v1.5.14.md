# v1.5.14 · 修复 v1.5.13 识别环节 AttributeError 错误风暴 / Fix AttributeError error storm in v1.5.13 team detection

## 中文

### 问题
v1.5.13 上线后 MuMu 自动战斗日志出现大量报错：`CombatCheck:do_check_in_combat` 每 ~100ms 抛一次
`AttributeError: 'AutoCombatTask' object has no attribute 'ANDROID_DETECT_THRESHOLD'`。

根因：`android_detect_team_identity()` 中阈值写成了 `self.ANDROID_DETECT_THRESHOLD`，
但该常量定义在模块级（`BaseWWTask.py` 顶部），不是类属性 → 运行时 AttributeError →
异常沿 `load_chars_android` → `load_chars` → `do_check_in_combat` 逐帧上抛，
战斗检查彻底瘫痪（错误风暴）。

### 修复
1. **直接根因**：`self.ANDROID_DETECT_THRESHOLD` → 模块级常量 `ANDROID_DETECT_THRESHOLD`。
2. **防线（自恢复要求）**：`load_chars_android` 中编队识别整段（锁定读取 + 自动检测）
   包裹 try/except——识别环节任何异常只记一条 `log_error`，随即走上游 PC 框兜底路径，
   保证 `load_chars` 不再被识别异常炸掉、战斗不中断。
3. **回归测试**：新增 `test_load_chars_android_survives_detect_exception`
   （识别抛 AttributeError 时必须兜底成功构建角色）；测试桩补 `log_error`。

### 验证
- `TestAndroidFormationLock.py` 31 项全绿；10 个安卓/云回归套件全部 OK。
- `restore.py` 部署 working + repo，`BaseWWTask.py` / `BaseCombatTask.py` 三处哈希一致。

## English

### Problem
After v1.5.13, MuMu auto-combat logs were flooded with errors: `CombatCheck:do_check_in_combat`
raised `AttributeError: 'AutoCombatTask' object has no attribute 'ANDROID_DETECT_THRESHOLD'`
every ~100ms.

Root cause: `android_detect_team_identity()` referenced the threshold as
`self.ANDROID_DETECT_THRESHOLD`, but the constant is module-level, not a class attribute →
AttributeError at runtime → propagated through `load_chars_android` → `load_chars` →
`do_check_in_combat` on every frame, crippling the combat check entirely (error storm).

### Fixes
1. **Direct cause**: `self.ANDROID_DETECT_THRESHOLD` → module-level `ANDROID_DETECT_THRESHOLD`.
2. **Safety net (self-recovery requirement)**: the whole team-identity step
   (locked identity read + auto detection) in `load_chars_android` is wrapped in
   try/except — any exception is logged once via `log_error`, then falls back to the
   upstream PC-frame path so `load_chars` can never be killed by detection errors again.
3. **Regression test**: added `test_load_chars_android_survives_detect_exception`
   (must fall back and still build chars when detection raises AttributeError);
   test stub now implements `log_error`.

### Verification
- `TestAndroidFormationLock.py` 31 tests green; all 10 android/cloud regression suites OK.
- Deployed via `restore.py` to working + repo; `BaseWWTask.py` / `BaseCombatTask.py`
  hashes identical across custom/working/repo.
