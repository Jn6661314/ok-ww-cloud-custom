# v1.8.1 · 修正远控/串流窗口的入口位置 + 配置名含斜杠的问题

## 背景

v1.8.0 的发布说明里写的是「**设置 → 远控/串流窗口(试验性)**」，但这是错的 —— 用户按这个路径
去「设置」页翻，翻不到。

原因：`ConfigOption(..., show_at_tab=True)` 的项会被设置页**主动跳过**：

```python
# ok/ui/qt/settings/settings_page.py
if getattr(option, 'show_at_tab', False):
    continue
```

它们只作为**左侧导航栏的独立页**出现：

```python
# ok/ui/qt/MainWindow.py
for name, config_obj, option in global_config.get_all_visible_configs():
    if getattr(option, 'show_at_tab', False):
        ...
        self.add_page(config_tab, option.icon, self.app.tr(option.name), SECTION_GAME)
```

所以「角色配置」「游戏热键」「MuMu 安卓 Config」「远控串流窗口」都是**左侧栏「游戏」分组里的页**，
不是设置页里的行。

## 一、入口在哪（正确说法）

1. 左侧导航栏 → **「游戏」分组** → 最下面；
2. 页名 **「远控串流窗口(试验性)」**，图标是**显示器**（v1.8.1 换的，原来和「角色配置」同为 users 图标，容易混）；
3. 侧边栏条目多时需要往下滚一点；
4. **它不在「设置」（齿轮）页里**，在设置页里怎么翻都翻不到。

`MuMu 安卓 Config` 同理，也在左侧栏「游戏」分组里。

## 二、修掉配置名含 `/` 的问题

框架按 `configs/<配置名>.json` 存全局配置，所以名字里的 `/` 会被当成**目录分隔符**：

```
configs/远控/串流窗口(试验性).json     ← 实际落到了子目录
configs/MuMu/安卓 Config.json          ← 同上
```

配置能读能写（框架会自动建目录），但目录结构会被搞乱，也不利于备份/迁移。

改名为（去掉斜杠）：

| 旧名 | 新名 | 配置文件 |
| --- | --- | --- |
| `远控/串流窗口(试验性)` | `远控串流窗口(试验性)` | `configs/远控串流窗口(试验性).json` |
| `MuMu/安卓 Config` | `MuMu 安卓 Config` | `configs/MuMu 安卓 Config.json` |

两个旧配置当时都是默认值（`Enable=false` / `MuMu 编队` 为空），改名不丢数据；
残留的 `configs/远控/`、`configs/MuMu/` 子目录已清理（内容备份在工作区
`.workbuddy/tmp/configs-legacy-slash-*`）。

同时新增一条单测，禁止任何全局配置名再出现 `/`：

```python
def test_global_config_names_have_no_slash(self):
    for option in config.config['global_configs']:
        self.assertNotIn('/', option.name, f'全局配置名不能含斜杠: {option.name!r}')
```

## 三、其他

- 配置项描述里补了一句「位置: 左侧导航「游戏」分组最下面(不在「设置」页里)」，
  打开该页就能看到自己是怎么被找到的；
- README / CHANGES / v1.8.0 发布说明 / `AGENT_INSTALL_PROMPT.md` 的路径表述全部改正，
  安装提示词里也要求 Agent **先把位置讲清楚**；
- 全量测试 **217 项通过**。

## 升级方式

照常 `python restore.py`（或按 `AGENT_INSTALL_PROMPT.md` 走），然后**重启 ok-ww**。
旧的 `configs/远控/`、`configs/MuMu/` 目录如果还在，可以直接删掉，配置会重新生成在 `configs/` 根下。

# v1.8.1 · Fix the entry point of the remote/stream window page, and a slash in config names

## Why

v1.8.0's notes said "**Settings → 远控/串流窗口(试验性)**", which is wrong. Options registered with
`ConfigOption(..., show_at_tab=True)` are **explicitly skipped by the settings page**:

```python
# ok/ui/qt/settings/settings_page.py
if getattr(option, 'show_at_tab', False):
    continue
```

They only exist as **standalone pages in the left sidebar** (`MainWindow.add_page(..., SECTION_GAME)`).
That's why the page simply isn't there when you open Settings.

## 1. Where it actually is

1. Left sidebar → **"Game" group** → bottom of the list;
2. Page name **「远控串流窗口(试验性)」**, icon is a **monitor** (changed in v1.8.1 — it used to share the
   `users` icon with "Character Config", which made it easy to miss);
3. Scroll the sidebar down a little if needed;
4. It is **not** inside the Settings (gear) page.

`MuMu 安卓 Config` lives in the same sidebar group.

## 2. Slash in config names

Global configs are persisted as `configs/<name>.json`, so a `/` in the name becomes a **path separator**:

```
configs/远控/串流窗口(试验性).json
configs/MuMu/安卓 Config.json
```

Reading/writing still worked (the framework creates the directory), but the folder layout got messy.
Renamed:

| Old | New | File |
| --- | --- | --- |
| `远控/串流窗口(试验性)` | `远控串流窗口(试验性)` | `configs/远控串流窗口(试验性).json` |
| `MuMu/安卓 Config` | `MuMu 安卓 Config` | `configs/MuMu 安卓 Config.json` |

Both old configs only held defaults, so nothing was lost. The leftover subdirectories were removed
(backed up under `.workbuddy/tmp/configs-legacy-slash-*`). A new unit test forbids `/` in any global
config name so this cannot regress.

## 3. Misc

- The option description now states its own location ("left sidebar → Game group, not Settings");
- README / CHANGES / v1.8.0 notes / `AGENT_INSTALL_PROMPT.md` corrected;
- **217 tests pass**.

## Upgrade

Run `python restore.py` as usual, then **restart ok-ww**. If `configs/远控/` or `configs/MuMu/` still
exist, you can delete them — the configs will be regenerated directly under `configs/`.
