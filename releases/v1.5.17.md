# v1.5.17 · MuMu 三项修复：活跃行迹 / 拉海洛方块 / 自动战斗与掉线 / v1.5.17 MuMu fixes: activity trace, Rahai Blocks, auto combat & disconnect

## 中文

### 背景（2026-11-25 日志实测）
1. **每日任务不查活跃度**：AndroidDailyTask 17:21 日志
   `total daily points 未识别 → 无法确认当前活跃度，为避免浪费体力将跳过体力刷取`。
   手游端索拉指南是移动端布局，PC 专属的"活跃行迹"子页签坐标与活跃度 OCR 区域
   全部落空，导致活跃度永远"未知"，每日任务保守跳过全部体力刷取。
2. **拉海洛方块在 MuMu 上失败**：17:36~17:38 连续 FatalTaskError。截图证实两个问题：
   - 玩家在**无尽模式**页面/对局时：无尽模式没有简单/困难难度选项，任务报
     "无法识别关卡页面当前选中的难度"，随后的固定坐标点击还可能误开局；
   - 开局首关弹出的**"无尽模式"玩法说明弹窗**（居中"确认"按钮）没有任何处理，
     挡住棋盘识别，任务报"无法识别棋盘"。
3. **自动战斗不触发（选中敌人也不打）**：根因是 ok-ww 进程 15:33 启动、早于 16:28
   的代码恢复，内存中仍是 v1.5.13 旧字节码——`self.ANDROID_DETECT_THRESHOLD`
   AttributeError 每 100ms 炸一次 `load_chars`（当日 7384 次），`_in_combat`
   永远无法成立，战斗永远不进入。**磁盘上的 v1.5.14+ 代码已修复此 bug，重启
   ok-ww 即可**（本版随 restore.py 重新部署）。
4. **频繁掉线**：日志显示挂机期每 180 秒整断线一次（10:57~11:24、12:15~13:00
   两个时段共 28 次），脚本自动重连链条有效（点确认 → 重登 → 回战斗），但
   部分掉线弹窗按钮文案是"重新登录"而非"确认"，旧候选匹配不到；且脚本无法
   根治模拟器网络层问题，缺少对用户的环境排查提示。

### 改动
- **DailyTask 安卓分支（活跃行迹）**：
  - `_android_open_activity_trace()`：点完征程页签后先检查页面是否已出现活跃度
    读数；没有则 OCR 定位"活跃行迹/每日活跃"文字并点击（超时仅告警）。
  - 进度识别：安卓端宽域 OCR `(\d{1,3})[/／]180`（兼容全角斜杠）。
  - `_android_total_daily_points()`：宽域 OCR 找 `x/100|x/200` 形式读数
    （分母限定过滤任务进度类计数），多候选时优先取与"活跃度"文字垂直距离最近的；
    重试 3 轮仍失败保持原有保守跳过 + "未识别"标记。
  - PC/云游戏路径完全不变。
- **RahaiBlocksTask MuMu 适配**：
  - `_tutorial_confirm()`：识别"无尽模式/玩家可以一直游玩…直到失败"玩法说明弹窗，
    点击居中"确认"；`_ready_board` 与 `_play_board` 弹窗处理链路均已接入。
  - `_endless_page()` + `_challenge_current_details`：无尽模式详情页明确提示
    "无尽模式暂不支持自动挑战，请打开简单/困难关卡详情页"，不再报含糊的
    "无法识别难度"。
  - `_selected_difficulty(wide=True)` / `_widest_selected_difficulty()`：手游端
    PC 标题区域读不到难度时，宽域扫描右栏；同时读到简单/困难页签时取最靠上的
    （标题区）作为当前选中难度。
  - `_challenge` 难度确认失败时不再直接放弃：宽域识别到任一难度即按当前选中
    难度继续（实际以详情页选中难度开打），仅记告警。
  - `_return_to_list()` 安卓兜底：X 坐标关闭详情页失败后，用安卓返回键
    （esc 已映射）重试，再失败才报错。
  - 对局交互沿用 Pynput 真实鼠标拖拽 + R 旋转（等同手动游玩），需保持 MuMu
    窗口前台。
- **BaseWWTask 掉线加固**：
  - `ANDROID_CONFIRM_TEXTS` 补充"重新登录/重新登錄/重新连接/重新連線"按钮变体，
    掉线弹窗按钮文案非"确认"时也能点掉。
  - 新增掉线频率统计：10 分钟内 ≥3 次掉线时，输出 MuMu 后台省电/限帧、
    networkReset.bat、DNS/加速器排查建议（通知每 30 分钟最多一次，日志即时记录）。

## English

### Background (from 2026-11-25 logs)
1. **Daily task never reads activity points**: AndroidDailyTask logged
   `total daily points unknown -> skip stamina farming`. The mobile guidebook
   layout differs from PC, so the PC-only sub-tab coordinates and OCR regions
   all missed, leaving activity "unknown" and skipping all stamina farming.
2. **Rahai Blocks fails on MuMu**: repeated FatalTaskError at 17:36-17:38.
   Screenshots confirm: the "Endless Mode" page has no Simple/Hard difficulty
   (task reported "cannot detect selected difficulty" and blind coordinate
   clicks could even start a level), and the first-run "Endless Mode" tutorial
   popup (centered "Confirm" button) blocked board detection.
3. **Auto combat never engages** (even with a manually locked target): the
   ok-ww process started at 15:33, before the 16:28 code restore, so it kept
   running stale v1.5.13 bytecode — `self.ANDROID_DETECT_THRESHOLD`
   AttributeError crashed `load_chars` every 100ms (7384 times that day),
   `_in_combat` could never be set. The v1.5.14+ code on disk already fixes
   this; **restart ok-ww** (redeployed with this release via restore.py).
4. **Frequent disconnects**: logs show disconnects every exactly 180 seconds
   during unattended runs (28 occurrences). The auto-relogin chain works, but
   some disconnect dialogs use a "Re-login" button instead of "Confirm",
   which the old candidate list missed; and the script lacked environment
   guidance since it cannot fix emulator-level network issues.

### Changes
- **DailyTask Android branch (activity trace)**:
  - `_android_open_activity_trace()`: after opening the quest tab, check whether
    the activity page is already visible; if not, OCR-locate and click the
    "活跃行迹" tab (timeout warns only).
  - Progress OCR on Android uses a wide-area `(\d{1,3})[/／]180` pattern.
  - `_android_total_daily_points()`: wide-area OCR for `x/100|x/200` readings
    (denominator filter excludes quest-progress counters); among multiple
    candidates prefer the one nearest the "活跃度" label vertically; 3 retry
    rounds before falling back to the conservative skip.
  - PC/cloud paths unchanged.
- **RahaiBlocksTask MuMu support**:
  - `_tutorial_confirm()`: detects the "Endless Mode" tutorial popup and clicks
    the centered Confirm; wired into both `_ready_board` and `_play_board`.
  - `_endless_page()` + `_challenge_current_details`: clear message that Endless
    Mode is not auto-challengeable instead of the vague "cannot detect difficulty".
  - `_selected_difficulty(wide=True)` / `_widest_selected_difficulty()`: when the
    PC title region misses on mobile, scan the right panel widely; if both
    Simple/Hard tabs appear, take the topmost (title area) as selected.
  - `_challenge` no longer aborts on difficulty-verification failure: if any
    difficulty is detected, continue with the currently selected one (warning
    logged).
  - `_return_to_list()` Android fallback: retry with the Android back key
    (esc remapped) when the X coordinate fails.
  - Board interaction keeps Pynput real-mouse drag + R rotation (same as manual
    play); the MuMu window must stay foreground.
- **BaseWWTask disconnect hardening**:
  - `ANDROID_CONFIRM_TEXTS` now includes "重新登录/重新连接" button variants.
  - New disconnect frequency tracking: with ≥3 disconnects in 10 minutes, log
    MuMu power-saving/frame-limit, networkReset.bat and DNS/accelerator advice
    (notification at most once per 30 minutes).

### Verification
- New `tests/TestAndroidMuMuFixes.py` (20 tests) all pass; 12 existing suites
  (FormationLock / AemeathRotation / RahaiBlocksEntry / RahaiFaults /
  AndroidDisconnect / CombatFix / CombatPersistence etc.) all green.
- Deployed to working + repo via `restore.py`; hashes consistent across the
  three copies.

### Important notes
- **Restart ok-ww**: one root cause of auto combat never engaging is stale
  bytecode in the old process; restart to apply v1.5.17 fully.
- If MuMu disconnects every ~3 minutes, it is an emulator/environment issue —
  follow the on-screen guidance; the script keeps auto-reconnecting.
