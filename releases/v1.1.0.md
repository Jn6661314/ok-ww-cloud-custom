# v1.1.0 · 故障方块机制 / 云 UID 遮罩 / 通关后卡住修复 / ADB 设备入口

## 中文

### 拉海洛方块·逆转 支持「故障方块」新机制（1 级 / 2 级故障）

- **视觉识别**：按教程图校准的故障特效特征（亮粉色噪点，BGR ≈ 242/105/207，覆盖约 90% 方块面），普通紫/蓝/橙/白图标方块不会误判（`rahai_blocks._fault_mask`）。
- **消除模拟**：故障方块与数据损坏方块一致——参与凑满行列消除但自身留在棋盘上，故障解除后重新读盘自动转为普通方块参与后续消除（`clear_lines(mask, fixed, fault)`）。
- **落块验证放宽**：故障解除残留、爆炸方块引爆导致的棋盘偏差不再中断挑战，改为告警并以重新读取的实际棋盘继续。
- **教程翻页识别新增「故障方块」「爆炸方块」标题**，开局说明页可自动跳过。
- 合成图像单测 `tests/TestRahaiFaults.py` 全部通过（视觉识别、消除模拟、规划器集成）。

### 云鸣潮 UID 遮罩

- 云游戏浏览器启动时注入持久遮罩层（`add_init_script`），盖住右下角 UID 区域（与 PC 端 `paint_uid_cover` 相同比例：宽 13% × 高 2.5%）。
- `pointer-events:none` 不影响鼠标点击；页面跳转后自动重新生效；CDP 截图中同样被遮住。
- 设备配置 `cover_uid` 可关闭（默认开启）。

### 通关后退回活动主页需要手动点「立即前往」

- 通关结算后游戏可能直接退回活动主页而不是关卡详情，任务此前会报"领取奖励后无法识别关卡详情"并停止。
- 新增 `_go_now_button()` OCR 识别「立即前往」，在 `_challenge` 领奖后与 `_return_to_list` 中自动点击返回关卡列表；若直接回到关卡列表也能正常继续。

### 玩法说明弹窗（如「1 级故障方块」）不会关闭

- 抽出 `_close_help_popup()`：检测到说明弹窗后先点右上角 X（归一化坐标 0.960/0.210），无效再依次用「确认」按钮、"切换至最后一页"跳转兜底。
- 挑战过程中弹出的说明弹窗（如故障方块首次出现时）此前会导致"棋盘消失"误报，现在下棋循环中检测到弹窗会自动关闭并继续。

### 本地安卓模拟器（ADB）设备入口

- `config.py` 新增 `adb` 配置节，设备选择列表里会出现已安装的安卓模拟器（如 MuMuPlayer 12）与 USB / 无线 ADB 设备：
  - `packages` 同时包含国服 `com.kurogame.mingchao` 与国际服 `com.kurogame.wutheringwaves`，框架按实际安装的游戏自动选择并拉到前台。
  - `capture_method` 默认 `'adb'`（通用截图，后台可用但约 300ms/帧）；**MuMuPlayer 12 用户可在设备连接弹窗的"捕获方式"里切换到 `Ipc`**，走模拟器原生截图通道，速度快得多。
  - 点击方式为框架自带的 `ADBInteraction`（`adb input` / 可选 uiautomator2），无需改动任务代码。
- 运行环境需要 `adbutils`（安装版 Python 自带环境如缺失，执行 `python -m pip install adbutils`）；adb.exe 由 adbutils 自带，无需单独安装 Android SDK。
- 实测：本机已装的 MuMuPlayer-15.0-0（`127.0.0.1:16384`）能被设备管理器正确识别，模拟器开机后即可连接。
- 注：这是"多一个设备入口"，任务里的浏览器/PC 专用判断逻辑未改动；ADB 设备上的完整任务流程（尤其实时战斗循环）请自行实测。

## English

### Rahai Blocks·Reversal now supports the new "fault block" mechanic (level 1 / level 2 faults)

- **Visual detection**: calibrated against the tutorial art, the fault effect shows bright pink noise (BGR ≈ 242/105/207, covering about 90% of the block face); ordinary purple/blue/orange/white icon blocks are not misdetected (`rahai_blocks._fault_mask`).
- **Clear simulation**: fault blocks behave like data-corrupted blocks — they contribute to filling a row/column for the clear but stay on the board; once the fault is lifted, re-reading the board converts them into normal blocks that participate in later clears (`clear_lines(mask, fixed, fault)`).
- **Relaxed placement validation**: leftovers from a lifted fault and board drift caused by explosions no longer abort the challenge; they raise a warning and the run continues with the freshly read board.
- **Tutorial paging detection** now recognizes the "故障方块" and "爆炸方块" titles, so the opening instruction page can be skipped automatically.
- The synthetic-image unit test `tests/TestRahaiFaults.py` passes fully (visual detection, clear simulation, planner integration).

### Cloud UID cover

- The cloud browser injects a persistent overlay at startup (`add_init_script`) covering the UID area in the bottom-right corner (same 13% width × 2.5% height ratio as the PC-side `paint_uid_cover`).
- `pointer-events:none` keeps mouse clicks working; the overlay re-applies after page navigation and is also covered in CDP screenshots.
- The device option `cover_uid` can disable it (enabled by default).

### Stuck on the activity page after clearing a stage

- After the results screen the game may return to the activity page instead of the stage details page; the task previously reported "cannot identify stage details after claiming rewards" and stopped.
- New `_go_now_button()` OCR recognises 「立即前往」 and clicks it automatically after claiming in `_challenge` and inside `_return_to_list`; returning straight to the stage list also works now.

### Gameplay help popups (e.g. "level 1 fault block") no longer stay open

- Extracted `_close_help_popup()`: once a help popup is detected it first clicks the top-right X (normalized coordinates 0.960/0.210), and falls back to the 「确认」 button and then to "switch to the last page".
- Help popups appearing during the challenge (e.g. the first time a fault block shows up) previously caused a false "board disappeared" report; now the drop loop detects the popup, closes it, and keeps going.

### Local Android emulator (ADB) device entry

- `config.py` gained an `adb` section, so installed Android emulators (e.g. MuMuPlayer 12) and USB / wireless ADB devices show up in the device list:
  - `packages` contains both the CN package `com.kurogame.mingchao` and the global package `com.kurogame.wutheringwaves`; the framework picks whichever is installed and brings it to the foreground.
  - `capture_method` defaults to `'adb'` (generic screencap, works in the background but roughly 300 ms/frame); **MuMuPlayer 12 users can switch to `Ipc` in the "capture method" dropdown of the device connection dialog** to use the emulator's native capture channel, which is much faster.
  - Interaction uses the framework's built-in `ADBInteraction` (`adb input` / optional uiautomator2); no task code changes required.
- Requires `adbutils` (if missing in the bundled Python, run `python -m pip install adbutils`); adb.exe ships with adbutils, so no separate Android SDK is needed.
- Tested: the locally installed MuMuPlayer-15.0-0 (`127.0.0.1:16384`) is recognized correctly by the device manager and connects once the emulator has booted.
- Note: this is "one more device entry" — the browser/PC-specific branches inside the tasks are unchanged; please test the full task flow on ADB devices yourself (especially the real-time combat loop).

### Upstream PR status

The customizations in this repository were split into 4 mutually independent upstream PRs that can be merged separately (all passed CI with SonarCloud Quality Gate OK):

- **[ok-wuthering-waves #1873](https://github.com/ok-oldking/ok-wuthering-waves/pull/1873)** — cloud support and per-account Cookie isolation.
- **[ok-wuthering-waves #1874](https://github.com/ok-oldking/ok-wuthering-waves/pull/1874)** — fault block support for Rahai Blocks·Reversal (`rahai_blocks.py` detection and clear semantics, `RahaiBlocksTask.py` integration, `tests/TestRahaiFaults.py`).
- **[ok-script #130](https://github.com/ok-oldking/ok-script/pull/130)** — cloud UID cover (the `cover_uid` option and overlay injection in `ok/device/capture_methods/browser.py`). `browser.py` belongs to the ok-script package (the ok-ww repository itself has no `ok/` directory), so this one goes to ok-script.
- **[ok-script #131](https://github.com/ok-oldking/ok-script/pull/131)** — per-account browser profile, login-state persistence and background input disguise (`user_data_dir` accepts a path or a callable + `OK_WW_CLOUD_PROFILE` environment fallback; `storage_state.json` is saved on close and cookies/localStorage restored on start; `background_input` disguise, enabled by default).

Note: the four PRs do not depend on each other; #130 and #131 both touch `browser.py`, so whichever merges first needs a rebase by the other (the changed regions differ, so conflicts are easy to resolve). Until the PRs are merged, these capabilities remain available as snapshots in this repository.
