# v1.6.0 · 以官方 v3.8.15 为基线重建（云端定制 + 无尽模式，不含 MuMu）

## 背景

上游 ok-wuthering-waves v3.8.15（ok-script 3.0.14）已经原生支持云鸣潮，并且解决了我们此前
自己实现的两件事：

1. **云鸣潮是一等设备**：`config['browser']`、`BaseWWTask.handle_cloud_disconnect()`、
   `CombatCheck` 里的 `CLOUD_*` 判定、`is_browser()` / `is_adb()` 分支都是官方代码。
2. **日常任务只注册一次**：`DailyTask` 内部按 `_executor.device_manager.get_preferred_device()`
   决定操作方式，不再是"云每日 / 本地每日"两个任务。用户只需要选设备，然后跑同一个日常。

所以本版把整份源码换成官方 v3.8.15，再把我们真正还需要的那部分定制重新合并上去。
MuMu / 安卓模拟器的全部定制**不合并**，完整保留在 `legacy-mumu-v1.5.21` 分支。

## 关键改动

### 1. UID 遮罩改走框架 `blur_area`

按 ok-script 维护者对 [PR #130](https://github.com/ok-oldking/ok-script/pull/130) 的意见：
不在通用框架里硬编码某个游戏的 UID 位置，而是使用框架已有的遮罩机制。

```python
def blur_area(width, height):
    """Bottom-right region where the game prints the UID (player id)."""
    return Box(width * 0.870, height * 0.975, width * 0.130, height * 0.025)
```

- `ok/core/screenshot.py::to_pil_image` 会对**所有保存的截图**应用模糊区域；
  `ok/task/TaskExecutor.py` 对**实时窗口**应用 overlay —— 两条路径同一份区域定义；
- 设置里「Enable Blur」可选 **Blur / Inpaint**（默认 Inpaint）、可调刷新间隔；
- 与 **WebRTC 视频流捕获**兼容：遮罩作用在取到的帧上，不依赖页面 DOM 合成；
- 框架侧不再有任何游戏专用注入，这部分**可以直接作为 ok-ww 的 PR**提交。

### 2. 多账号任务内的两个云端按钮

`src/task/MultiAccountDailyTask.py`（官方文件 + 云端分支）：

- `config_type` 改为按设备动态的 property：云设备下注入
  `云鸣潮账号操作 = {'buttons': [保存登录状态, 切换账号]}`，并隐藏 `Per-account Configuration`
  （云端账号由「配置账号」管理，不需要再切两套配置）；PC / 安卓下移除该分组；
- `run()` 增加云分支 `_run_cloud()`：按账号依次 `prepare_live_profile` → 跑官方 `run()` 流程 →
  记录结果；单个账号失败不中断整轮，全部完成后汇总；
- 「保存登录状态」把当前 `cache/playwright` 目录整体搬回该账号的 profile 目录；
- 「切换账号」在 **daemon 线程**里"关浏览器 → 换目录 → 开浏览器"，用 Qt Signal 回主线程弹结果，
  避免 `.result(timeout)` 卡住 UI；两个按钮在非云设备上点击会直接提示不可用。

### 3. 账号登录态隔离（纯 ok-ww 侧）

官方 Playwright 持久化上下文固定使用 `cache/playwright`，没有 `user_data_dir` / `storage_state`
配置项 —— 三个账号会共用同一份 Cookie 互相顶号。本版在 `src/cloud_browser.py` 里用
**目录整体换入换出**解决，不碰框架：

```text
cache/playwright               ← 当前运行账号的 live 目录（框架只认这个路径）
configs/cloud_profiles/<key>/  ← 每个账号一份完整 profile（含 .okww_account 标记）
```

`prepare_live_profile()` / `adopt_live_profile()` / `migrate_legacy_profile()` 负责搬迁，
`restart_browser()` / `switch_account()` 负责关浏览器 → 换目录 → 重开。原有的
`storage_state.json` 快照保留作为兜底。

### 4. 拉海洛方块：官方新版 + 无尽模式重新实现

官方 `RahaiBlocksTask.py`（373 行）替换我们此前的 657 行定制版（那版夹带了大量 MuMu 适配）。
官方版本本身有两个致命问题，本次在官方代码结构上补齐：

**a. 官方版在云鸣潮下不可用**：`run()` 里硬性要求 `self.hwnd.exists`（PC 窗口句柄），
并且用 `PynputInteraction` 发真实鼠标事件。云鸣潮没有游戏窗口，直接抛
"拉海洛方块需要处于前台的 Windows PC 客户端"。现在按设备分流：云鸣潮用
`BrowserInteraction`（CDP 虚拟输入）、跳过窗口句柄检查、`clickable()` 恒为真
（浏览器窗口被挡住也能操作）。

**b. 官方版不支持无尽模式**：无尽关卡没有「简单/困难」页签，官方会走到
`无法选择{difficulty}难度` 然后退页——正是旧版 v1.5.19 修过的那个坑。现在补齐：

| 能力 | 行为 |
| --- | --- |
| 无尽详情页直启 | `_endless_page()` 认「无尽模式」/「玩家可以一直游玩」/局内计分文案，跳过难度与积分/奖章目标检查 |
| 加入进行中的对局 | 棋盘可见即直接接着玩（`_endless_ingame()`） |
| 达标结算 | 局内解析「达到N分结算」，每 10 步读一次左上分数，达标后点 X → 离开 → 领奖 |
| 玩法说明弹窗 | 首局「确认」弹窗（`_tutorial_confirm`）与常规机制说明（`_dismiss_help`）都会点掉 |
| 无合法落点 / 棋盘消失 | 无尽模式返回 `dead` / `ended` 交给游戏自行结算，不再当成失败抛异常 |
| 详情页直接开始 | 停在任一关卡页也能跑：按当前选中难度开打，读不到难度就用宽域「开始」按钮兜底 |
| 通关退回活动主页 | 自动点「立即前往」回到关卡列表 |

`_play_board` 因此多了一个 `endless` 分支并返回结束原因
（`goal` / `cap` / `dead` / `ended` / `reward`），普通关卡的失败语义完全不变。

**c. 走棋搜索预算**（`src/task/rahai_blocks.py::choose_move`）：任意托盘大小都做束裁剪
（`CHOOSE_MOVE_BEAM_WIDTH = 96`）+ `CHOOSE_MOVE_TIME_BUDGET = 3.0` 秒墙钟上限。原算法只在
3 块托盘时裁剪，4 块托盘（无尽模式）时中间状态不收敛，单次搜索要评估上千万盘面、
纯 CPU 卡死数分钟（v1.5.20 的关机线程转储实证）。

### 5. 每日任务的云端适配（保留自旧版）

- 活跃度（总积分）识别改为多区域重试，读不到返回 `None` 并只记一条 warning，
  不再当 0 处理 —— 避免"活跃度读失败 → 以为要刷体力"和"读失败 → 以为已完成"两种误判；
- 战斗通行证（先约电台）在浏览器模式下不按 Alt，改多候选坐标 + 文字兜底。

## 已知差异（旧版有、本版没有）

- 「故障方块 / 爆炸方块」机制识别（以及 `rahai_blocks.py` 里的 fault 位运算）——
  官方 v3.8.15 的棋盘模型没有 fault 概念，本次按"只合并云端"没有一并移植；
- MuMu / 安卓模拟器的全部定制（完整保留在 `legacy-mumu-v1.5.21` 分支）。

无尽模式、详情页直接开始、玩法说明弹窗、通关退回主页的「立即前往」**已重新实现**，不是丢失项。
