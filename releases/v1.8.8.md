# v1.8.8 · 云鸣潮战斗奖励副本出错后现场续打，不再重进 / Resume the reward dungeon in place after a cloud error

本版改了运行时代码，**必须重跑 `python restore.py` 并重启 ok-ww** 才生效。

## 问题

多账号日常里在无音区（Tacet Suppression）等战斗奖励副本中出错时，错误恢复会先重启云游戏
浏览器，然后 `wait_cloud_ready() → ensure_main()`。云游戏会话其实还停在副本里，而
`ensure_main()` 看到 `in_realm()` 会按 Esc + 确认框**退出副本**；DailyTask 随后又从 F2
图鉴**重新进本**。结果这一场白打，云游戏延迟大时还会多扣体力。

## 现在的行为

出错瞬间若探测到仍在战斗奖励副本（`src/reward_dungeon_recovery.py`），浏览器重启后：

1. 等云端画面回到副本（不发送 Esc；一旦明确回到大世界就放弃等待）；
2. 还在战斗 → `combat_once` **续打当前这场**；
3. 探测战斗是否结束（血量/锁定图标消失），避免把没打完当打完；
4. 有「领取」F 提示或宝箱 → **按 F 领取奖励**；
5. 从副本菜单正常退出，把控制权交回原任务流程。

续打成功时跳过 `ensure_main()`，`MultiAccountDailyTask.work()` 也不再重复等待进入游戏；
剩余任务照常执行。若体力还有剩余，DailyTask 之后按原本规则再开下一场——这属于正常刷取，
不是因为出错而把当前场次丢掉重进。

不在副本时完全走原恢复路径；探测失败、续打异常、云端会话已经回到首页也都安全回退。
高级用户可在任务配置里放 `"Cloud Resume Reward Dungeon": false` 关闭该行为（默认开启）。

**边界**：只在「错误发生时确认仍在副本」时触发；如果出错时画面已经卡在图鉴/结算页，
或重启后云端会话被重置回云游戏首页，就按原流程从大世界重新开始。

---

English summary: when a cloud run fails inside a combat reward dungeon (e.g. Tacet Suppression),
the old recovery restarted the browser and then called `ensure_main()`, which presses Esc to
leave the dungeon; the daily task re-entered from the guidebook and lost the current fight.
The new recovery snapshots the in-dungeon state before restarting, then resumes combat, waits
for the fight to end, presses F to claim the reward, and leaves the dungeon normally — skipping
the re-entry path. It falls back to the original flow whenever the game is not in a reward
dungeon, or the snapshot/resume is inconclusive.
