# v1.5.10 · 修复 MuMu"打着打着莫名其妙不打了" / Fix MuMu combat stopping unexpectedly

发布日期 / Date: 2026-11-25

## 问题 / Problem

- **中文**：MuMu 自动战斗频繁中途停止。日志反复出现 `target lost try retarget` → `target_enemy failed, try recheck break out of combat`，而现场截图（12:13:59 / 12:18:36）里 boss 血条明明可见、角色正在战斗。
- **English**: MuMu auto combat stops frequently mid-fight. Logs show repeated `target lost try retarget` → `target_enemy failed, break out of combat`, while the现场 screenshots (12:13:59 / 12:18:36) show the boss health bar clearly visible and the character mid-fight.

## 根因 / Root Cause

- **中文**（日志 + 截图证据链）：
  1. PC 端有"血条仍在 → 30 秒耐心重锁"的路径，但安卓端 `has_target()` 与血条是**同一个判定**，血条一消失就走默认 3 秒重锁定 → 失败即 `break out of combat`。
  2. boss 潜地 / 无敌帧 / 无音区切波次期间血条本来就会消失一段时间，属于正常现象，却被当成了战斗结束。
  3. 重锁定失败一次就直接退出，没有二次确认。
  4. MuMu 抓屏偶发整帧黑（日志大量"抓屏返回空画面"），黑帧会被当"无敌人"。
- **English**:
  1. PC has a "30s patient retarget while the bar is still visible" path, but on Android `has_target()` **is** the health-bar check, so any bar gap falls straight to the default 3s retarget → break out.
  2. Buried/invulnerable boss phases and wave transitions legitimately hide the bar for a while — misread as "combat over".
  3. A single retarget failure breaks out with no retry.
  4. MuMu capture occasionally returns an all-black frame (see the flood of "抓屏返回空画面" warnings), which reads as "no enemy".

## 修复 / Fix

全部在 `src/combat/CombatCheck.py`，PC / 云游戏行为不变。/ All in `src/combat/CombatCheck.py`; PC/cloud unchanged.

### 中文

- **安卓无血条重锁定耐心 3 → 8 秒**（`ANDROID_RETARGET_TIMEOUT`）。
- **重锁定失败先重试一轮**（6 秒）再退出战斗，两次都失败才 `break out`。
- **等待 Y 键锁敌期间继续普攻**：安卓无坐标点击 = 右下角攻击按钮，敌人重新出现时保持输出，不再站着干等。
- **连续无敌人退出窗口 2 → 4 秒**（`ANDROID_NO_ENEMY_EXIT`）。
- **整帧黑/空帧保护**（`_android_frame_is_dead()`）：黑帧期间保持 in_combat 等抓屏恢复，最多 20 秒（`ANDROID_FRAME_DEAD_MAX`），超时走正常判定避免永久挂起。
- PC 端保留原逻辑：`retarget_timeout = 30 if has_health else target_enemy_time_out`、无敌人窗口 2 秒。

### English

- Android no-bar retarget patience 3 → **8s** (`ANDROID_RETARGET_TIMEOUT`).
- **Retry one full retarget round** (6s) before breaking out of combat.
- **Keep attacking while waiting for the Y-lock**: Android coordinate-less click = attack button, so damage continues as soon as the enemy re-emerges.
- No-enemy exit window 2 → **4s** (`ANDROID_NO_ENEMY_EXIT`).
- **Black/empty frame guard** (`_android_frame_is_dead()`): stay in combat while frames are dead, up to 20s (`ANDROID_FRAME_DEAD_MAX`), then fall through to normal checks.
- PC keeps the original logic (`30s / has_health`, 2s no-enemy window).
