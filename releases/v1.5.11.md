# v1.5.11 · 修复 MuMu 切人（只有 1/2 键 / 动态映射 / 发键后核实） / Fix MuMu character switching (keys 1/2 only, dynamic mapping, post-press verification)

发布日期 / Date: 2026-11-25

## 问题 / Problem

- **中文**：MuMu 端切人有问题。模拟器键位映射里只有 **1 和 2** 两颗切换键，而脚本某些情况会去按 3 键；切人偶尔切错角色后战斗逻辑失配。
- **English**: Character switching misbehaves on MuMu. The emulator keymap has only **keys 1 and 2** bound for switching, but the script sometimes presses 3; a wrong switch leaves the combat logic desynced from the actual character.

## 根因 / Root Cause

- **中文**：
  1. 旧兜底映射 `ANDROID_DEFAULT_SWITCH_KEYS = {0:'1', 1:'2', 2:'3'}`，`android_switch_key()` OCR 读不到"切换角色N"提示时还会回退 `str(index+1)` —— 两条路径都会发出 **3 键**。MuMu 上 3 键没有绑定，按了等于没按，切 3 号位永远失败，10 秒后 `failed switch chars` 中断战斗。
  2. MuMu 的两颗切换键对应队伍栏的两个**非出战**队友按钮，按钮内容随出战角色动态变化，键->角色映射不是固定的；OCR 键位提示缺失时旧代码没有按当前角色推导的能力。
  3. 发切人键后直接把逻辑下标推进到目标值，**不核实画面**。按错键时脚本以为切成了，实际还在原角色上，后续连招全部打在错误的角色假设上。
- **English**:
  1. The old fallback map `{0:'1', 1:'2', 2:'3'}` and the `str(index+1)` fallback both emit **key 3**, which has no MuMu binding — switching to slot 3 always fails and breaks combat after 10s.
  2. The two switch keys are bound to the two **non-active** teammate buttons whose contents change with the active character; the mapping is dynamic and the old code could not derive it from the current character when OCR hints were missing.
  3. After pressing, the logical index was advanced to the target **without verification** — a wrong keypress made the script believe the switch succeeded while the game stayed on the old character.

## 修复 / Fix

`src/task/BaseWWTask.py` + `src/task/BaseCombatTask.py`，PC / 云游戏行为不变。

### 中文

- 移除含 3 键的默认映射，新增 `ANDROID_SWITCH_KEYS = ('1', '2')`，任何路径都不会再发 3 键。
- `android_switch_key(index, exclude=...)` 动态推导，优先级：
  1. OCR 读到的"切换角色N"键位提示；
  2. 同队另一个队友已确认的键 → 剩下那颗必然归本槽位；
  3. 兜底规律（实测出战 3 号位时键 1 切 2 号位）：键 1 给编队靠后的队友；
  4. `exclude` 里的键是本轮已按过但没生效的，自动换另一颗键。
- 新增 `android_confirm_switch(target)`：发键后等待动画落定、抓新帧，用编队徽章核实实际出战角色（缺哪个徽章当前就是哪个槽位），核实结果写回逻辑下标。
- `switch_next_char()` 安卓分支：按错键时不再盲目推进，记录已试过的键，下一轮自动换另一颗键重试；徽章 OCR 抖动读不到时保持原来的乐观推进，不让切人卡死。
- OCR 键位提示不再预填默认值，映射随出战角色实时变化。

### English

- Removed the key-3 default map; added `ANDROID_SWITCH_KEYS = ('1', '2')` — key 3 is never sent on any path.
- `android_switch_key(index, exclude=...)` now derives the mapping dynamically:
  1. OCR "切换角色N" key hints;
  2. the confirmed key of the other teammate → the remaining key belongs to this slot;
  3. fallback rule (measured: with slot 3 active, key 1 switches to slot 2): key 1 goes to the later team slot;
  4. keys in `exclude` (already tried without effect) are skipped, so the other key is tried automatically.
- New `android_confirm_switch(target)`: after each press, wait for the animation, grab a fresh frame and verify the actual active character via the formation badges (the missing badge is the active slot), writing the result back to the logical index.
- `switch_next_char()` Android branch no longer advances blindly on a wrong keypress; it records tried keys and retries with the other one. If badge OCR is unreadable during the switch animation, the old optimistic advance is kept so switching never deadlocks.
- OCR key hints no longer prefill defaults; the mapping tracks the active character in real time.
