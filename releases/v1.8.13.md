# v1.8.13 · MuMu 方块旋转改走可配置键位映射键 / MuMu Blocks rotation via configurable keymap key

本版改了运行时代码，**必须重跑 `python restore.py` 并重启 ok-ww** 才生效。

## 现象

v1.8.12 的双指触控方案里，旋转靠 slot 1 点屏幕上「旋转」按钮的固定坐标
`物理(x,y)=(游戏y,游戏x)`。但 MuMu 的触控是 1080x1920 物理屏 + 1920x1080 逻辑显示
（`logicalFrame=1920x1080`），中间有 InputFlinger 旋转层，直接写物理坐标的映射在
窗口尺寸变化/缩放时会失效。实测日志：

```
Placement preview did not match: slot=0, turns=0, row=3, col=1
无尽模式挑战失败：连续三次未能匹配落点预览。
```

连续三次落子预览不匹配 → 挑战失败 → 卡在结算弹窗，方块实际没放下去。

## 修复：旋转交给 MuMu 键位映射（可配置）

手游不认 `input keyevent` 的旋转键，但 **MuMu 键位映射可以把一个真实键盘按键
转成屏幕上的旋转点击**（项目里 `BaseWWTask._adb_real_key` 已是这套机制）。
现在方块旋转改成：

1. **新增配置项 `Rotate Key (MuMu Keymap)`**（默认 `f1`）——在 ok-ww 的方块任务
   设置里可改。请先在 **MuMu 键位映射**里把同一个键绑到游戏内的「旋转」按钮，
   并选一个**不与现有键位冲突**的键（默认 `f1` 与游戏热键 q/r/e/t/space/lshift/tab/f2/b 都不冲突）。
2. 旋转时发这个键的**真实键盘事件**，由 MuMu 键位映射完成旋转——旋转坐标不再由
   我们猜，不受窗口尺寸/缩放影响。
3. 拖拽仍走 sendevent（slot 0），与旋转互不干扰；键位映射键发送失败时**自动回退**
   到原来的点屏幕旋转按钮坐标（slot 1），双保险。
4. 保留 v1.8.12 的 IPC 抓屏（免前台）；只在旋转发键的瞬间把 MuMu 窗口切前台
   （Pynput 真实键盘的固有限制，与项目其它任务的键位映射行为一致）。

## 你需要做的

1. 在 **MuMu 模拟器 → 键位映射**里，给鸣潮加一个键位：把 `F1`（或你选的键）
   映射到游戏内左侧的圆形「旋转」按钮；确认这个键不和已有键位冲突。
2. 重跑 `python restore.py`，重启 ok-ww。
3. ok-ww 方块任务设置里 `Rotate Key (MuMu Keymap)` 保持默认 `f1`（若你改了键位映射的键，
   这里同步改成同一个键名，如 `f3`、`g` 等）。留空则回退为点屏幕按钮（不推荐）。
