# v1.5.12 · 修复声骸副本炸每日任务 + 队伍识别改为以编队为准 / Fix Tacet crash killing daily task + formation-based team identification

发布日期 / Date: 2026-11-25

## 问题 / Problem

- **中文**：
  1. MuMu 每日任务在声骸副本（无音区）"走向奖励"阶段崩溃：`walk_to_treasure` 30 秒找不到宝箱图标，抛 `WaitFailedException`，整个 AndroidDailyTask 停止。
  2. MuMu 队伍识别有问题；要求以配置的编队为准，不要在战斗期间做画面识别。
- **English**:
  1. MuMu daily task crashes in the Tacet field at "walk to reward": `walk_to_treasure` fails to find the treasure icon for 30s and raises `WaitFailedException`, killing the whole AndroidDailyTask.
  2. MuMu team identification misbehaves; it should be based on the configured formation, without on-screen identification during combat.

## 根因 / Root Cause

### 声骸副本崩溃（截图证据链）

- **中文**：失败现场截图（13:00:48）显示**残象其实还没清完**——"清理无音区中涌现的残象：2/3"，最后一只血条仍在、伤害数字仍在飞。`combat_once` 在残象切波次/清怪间隙误判"战斗结束"→ 脚本开始走向奖励 → 宝箱根本没刷出来 → 找图标 30 秒超时。
- 上游 `clear_tacet_and_reach_reward` 有"回去继续打"的恢复路径，但它依赖 `in_realm()`（PC 模板），手游端识别不到 → 恢复不生效 → 异常一路炸到 TaskExecutor，每日任务终止。
- **English**: The failure screenshot shows the last echo still alive ("clear echoes 2/3"). `combat_once` misjudged "combat over" during a wave transition; the chest never spawned, so the icon never appeared. The upstream recovery path depends on `in_realm()` (PC template) which never matches on mobile, so the `WaitFailedException` propagated and killed the daily task.

### 队伍识别

- **中文**：战斗期间对队伍栏做徽章 OCR，技能特效/伤害数字/切人动画会干扰识别，造成当前角色误判。按用户要求改为**以配置的编队为准**，战斗中不做画面识别。
- **English**: In-combat badge OCR is disturbed by combat VFX / damage numbers, misreading the current character. Per user request, identification now follows the configured formation with no on-screen OCR during combat.

## 修复 / Fix

`src/task/BaseWWTask.py` + `src/task/BaseCombatTask.py`，PC / 云游戏行为不变。

### 中文

1. **walk_to_treasure 手游端自恢复**：
   - 找宝箱图标超时（`WaitFailedException`）在安卓端不再上抛；
   - 先 `wait_combat` 检查是否仍有残象：有 → `combat_once` 清完再重走一次；
   - 仍无战斗也无宝箱 → 交回上层 `pick_f` / `has_claim_stamina` 判断（farm 循环自带 rechallenge 恢复），每日任务继续跑。
2. **队伍识别以编队为准**：
   - 移除战斗期间的队伍栏徽章 OCR（`_read_android_party_badges` / `android_confirm_switch` 及相关常量）；
   - 新增 `android_team_size()`：人数按已加载的编队角色（编队配置几个人就是几人队），默认 3 人；
   - `in_team_android()` 当前角色用脚本维护的逻辑下标，不再读画面；
   - 切人键按编队规则推导：键 1 → 编队靠后的非出战队友（实测出战 3 号位时键 1 切 2 号位），键 2 → 靠前的；永不发 3 键。

### English

1. **walk_to_treasure self-recovery on Android**: a treasure-icon timeout no longer propagates. It first checks whether echoes are still alive (`wait_combat`) — if so, resumes `combat_once` and retries the walk once; otherwise it hands control back to the farm loop's own rechallenge recovery instead of killing the daily task.
2. **Formation-based team identification**: removed the in-combat badge OCR machinery; team size now follows the loaded formation characters (default 3); the current character is the script-maintained logical index; switch keys are derived from the formation rule (key 1 → the later non-active slot), never sending key 3.
