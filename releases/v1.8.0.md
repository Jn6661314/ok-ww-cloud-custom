# v1.8.0 · 试验性：把远控 / 串流软件窗口当作 PC 设备

## 背景

UU远程、ToDesk、向日葵、Parsec、Moonlight 这类软件，做的事其实很简单：把**被控电脑的画面**
显示成本机的一个窗口，再把本机的键鼠事件转发过去。

既然如此，「抓这个窗口 + 往里发真实键鼠事件」就等于在操作被控电脑上的游戏 ——
走的还是 PC 客户端那条 windows 抓屏 + Pynput 链路，不需要任何"远程"专用逻辑。

本版把它做成一个**试验性开关**：设置里填窗口标题关键字即可，不填就完全不影响现有 PC / 云 / MuMu 行为。

## 一、怎么开

> **它在哪（v1.8.1 更正）**：左侧导航栏**「游戏」分组最下面的独立页**，名字是 **「远控串流窗口(试验性)」**
> （图标是显示器）。**它不在「设置」页里** —— 这类配置项会被设置页主动跳过，只作为独立页出现；
> 侧边栏可能需要往下滚一点。

1. 左侧导航栏「游戏」分组 → **远控串流窗口(试验性)** → 勾选 `Enable`；
2. `Window Title` 填标题关键字（正则，忽略大小写）：`UU远程` / `ToDesk` / `SunloginClient` / `Parsec`，
   多个可写成 `UU远程|ToDesk|Parsec`；
3. 保存并**重启 ok-ww**（配置只在启动时读取一次）；
4. 设备下拉里只剩一个条目，名字就是远控窗口标题，选中它照常跑任务。

开启后鸣潮 PC 客户端不再出现在设备列表（同一时间只驱动一个窗口），取消勾选重启即可切回。

## 二、实现

| 改动 | 文件 | 说明 |
| --- | --- | --- |
| 新增配置项 | `config.py` | `远控/串流窗口(试验性)`：`Enable` / `Window Title` / `Force Pynput`，加入 `global_configs` |
| 读取并应用配置 | `src/stream_window.py`（新） | `stream_window_settings()` 读配置、`apply_stream_window()` 调设备管理器；未开启 / 标题为空 / 无设备管理器都安全返回 False |
| 启动时挂载 | `src/globals.py`（新） | 官方 `Globals` + 一处 hook。框架在构造 `my_app` 之前已准备好 `og.device_manager`，因此这里改设备一定早于 GUI 刷新设备列表 |
| 切换匹配规则 | `ok/device/DeviceManager.py::set_stream_window` | 清掉 `windows.exe`（`Client-Win64-Shipping.exe`）与 `hwnd_class`（`UnrealWindow`）、`top_hwnd_class`，改为标题正则；强制 `PynputInteraction`；重新指向已有 `HwndWindow` |
| 禁用自动 resize | 同上 | 按实例把 `hwnd_window.try_resize_to` 置为返回 False —— 远控窗口的尺寸由远控软件决定，程序去 resize 只会把画面拉变形或加黑边 |
| 按 16:9 找画面区 | `ok/device/DeviceManager.py::do_start` | 远控模式下把 16:9 参考尺寸传给 `find_hwnd`：先找窗口内部 16:9 的子窗口（裁掉标题栏/工具条），`HwndWindow` 再按比例裁掉多余高度 |
| 忽略残留 exe 过滤 | `ok/device/DeviceManager.py::update_pc_device` | `devices.json` 里可能残留上次选中的鸣潮 exe，远控模式下必须忽略，否则拿 exe 过滤远控窗口永远匹配不到 |
| 不建占位设备 | 同上 | 远控窗口还没打开时不生成「未连接」设备，让启动流程去等窗口出现，而不是走进"启动游戏"分支误报「游戏路径不存在」 |
| 比例校验 | `ok/device/DeviceManager.py::check_stream_window_resolution` | 启动后检查客户区宽高比，非 16:9 时日志 + 通知给出**实际尺寸**和修正建议（不阻断运行） |

## 三、硬性要求（不满足就会坐标偏移 / 识图失败）

| 项目 | 要求 |
| --- | --- |
| 被控电脑 · 游戏 | **全屏运行**（独占全屏或窗口化全屏均可），不要留在窗口模式 |
| 被控电脑 · 分辨率 | **16:9**，且是 ok-ww 支持的档位：`1920x1080` / `2560x1440` / `1600x900` / `1280x720` |
| 远控软件 · 画质 | 「原画 / 原始分辨率」，**不要**「自适应」「缩放填充」「智能降分辨率」 |
| 本机 · 窗口尺寸 | 远控窗口**客户区**必须 16:9 且画面铺满；有黑边会被裁切或整体偏移 |
| 本机 · 前台 | 窗口必须**前台**、不最小化、不被遮挡（`PynputInteraction.clickable()` 会检查前台，否则点击被跳过） |
| 权限 | ok-ww 必须**以管理员身份运行**（Pynput 注入系统键鼠需要） |
| 鼠标模式 | 远控端选**绝对定位 / 直接控制**；「锁定鼠标 / 相对移动」会让点击整体偏移 |

## 四、已知限制

- 远控窗口开晚了（先点开始、后开窗口）不会立刻生效，等窗口出现后在设备下拉刷新即可；
- 只支持一个远控窗口；多开请用多账号任务，而不是多个设备；
- 远控软件有压缩与延迟，识图比本地 PC 更脆：认不出界面时优先提高画质，而不是调阈值；
- 与云游戏（`browser` 设备）、MuMu/安卓互斥，不能同时启用。

## 五、测试

新增 `tests/TestStreamDevice.py`（22 项）：配置注册与默认值、`stream_window_settings` 的三个分支、
`apply_stream_window` 的四个分支（正常 / 未开启 / 标题空 / 无设备管理器）、`set_stream_window`
的重写结果（正则、去 exe/class、强制 Pynput、禁用 resize）、比例校验（16:9 通过 / 16:10 告警 / 未开启跳过）、
远控窗口缺失时不建占位设备、`Globals` 初始化不抛异常。

全量 **215 项测试通过**（原 193 + 新增 22）。

# v1.8.0 · Experimental: use remote-control / streaming windows as a PC device

## Why

Tools such as UU Remote, ToDesk, Sunlogin, Parsec and Moonlight all do the same thing: they render the
**remote PC's screen into a local window** and forward local keyboard/mouse events to it.

So "capture that window + send real keyboard/mouse events into it" is already equivalent to playing on the
remote machine — it is the very same windows-capture + Pynput path used for the local PC client. No
remote-specific logic is required.

This release exposes that as an **experimental switch**: fill in a window-title keyword and it works;
leave it empty and nothing about PC / cloud / MuMu behaviour changes.

## How to enable

1. **Left sidebar → "Game" group → 「远控串流窗口(试验性)」** (the page with the monitor icon),
   tick `Enable`. Note: this page is **not** inside Settings — settings pages skip these options.
2. `Window Title` = title keyword (case-insensitive regex): `UU远程`, `ToDesk`, `SunloginClient`, `Parsec`,
   or several at once: `UU远程|ToDesk|Parsec`.
3. Save and **restart ok-ww** (the setting is read once at startup).
4. The device dropdown now contains a single entry named after the remote window — select it and run tasks.

While enabled, the local Wuthering Waves client no longer appears in the device list (only one window is
driven at a time). Untick `Enable` and restart to switch back.

## Implementation

| Change | File | Notes |
| --- | --- | --- |
| New config option | `config.py` | `远控/串流窗口(试验性)`: `Enable` / `Window Title` / `Force Pynput`, registered in `global_configs` |
| Read & apply | `src/stream_window.py` (new) | `stream_window_settings()` reads the option, `apply_stream_window()` calls the device manager; returns False safely when disabled / empty title / no device manager |
| Startup hook | `src/globals.py` (new) | Official `Globals` plus one hook. The framework prepares `og.device_manager` before `my_app`, so this always runs before the GUI refreshes the device list |
| Matching rule | `ok/device/DeviceManager.py::set_stream_window` | Clears `windows.exe` (`Client-Win64-Shipping.exe`), `hwnd_class` (`UnrealWindow`) and `top_hwnd_class`; matches by title regex; forces `PynputInteraction`; re-points the existing `HwndWindow` |
| No auto-resize | same | Per-instance `hwnd_window.try_resize_to` returns False — the remote window's size belongs to the streaming software; resizing it only deforms the picture or adds letterboxing |
| 16:9 content lookup | `ok/device/DeviceManager.py::do_start` | In stream mode a 16:9 reference size is passed to `find_hwnd`, so it first looks for a 16:9 child window (dropping title/tool bars); `HwndWindow` then crops the remaining height |
| Ignore stale exe | `ok/device/DeviceManager.py::update_pc_device` | `devices.json` may still hold the previously selected game exe; it must be ignored, otherwise the exe filter never matches the remote window |
| No placeholder device | same | If the remote window is not open yet, no "disconnected" device is created; the start flow then waits for the window instead of entering the launch branch and reporting "game path does not exist" |
| Aspect check | `ok/device/DeviceManager.py::check_stream_window_resolution` | After start, the client-area ratio is checked; a non-16:9 window produces a log + notification with the actual size and how to fix it (non-blocking) |

## Hard requirements

| Item | Requirement |
| --- | --- |
| Remote PC · game | Must run **fullscreen** (exclusive or borderless) |
| Remote PC · resolution | **16:9** and one of `1920x1080` / `2560x1440` / `1600x900` / `1280x720` |
| Streaming software · quality | "Original / native resolution" — **not** adaptive / stretch / smart downscale |
| Local · window size | The window **client area** must be 16:9 with the picture filling it; black bars cause cropping or offset |
| Local · foreground | The window must stay in the foreground, not minimized or covered (`PynputInteraction.clickable()` checks this, otherwise clicks are skipped) |
| Privileges | ok-ww must run **as administrator** (Pynput injects system-level input) |
| Mouse mode | Use absolute positioning / direct control; "locked mouse / relative movement" causes a constant offset |

## Known limitations

- If the remote window opens late, the device is not picked up until the list is refreshed;
- Only one remote window is supported — use the multi-account task for multiple accounts, not multiple devices;
- Streaming compression/latency makes recognition more fragile than a local PC: raise the stream quality first, do not lower thresholds;
- Mutually exclusive with the cloud (`browser`) device and MuMu/Android.

## Tests

New `tests/TestStreamDevice.py` (22 cases): config registration and defaults, the three branches of
`stream_window_settings`, the four branches of `apply_stream_window`, the rewrite performed by
`set_stream_window` (regex, cleared exe/class, forced Pynput, disabled resize), the aspect check
(16:9 pass / 16:10 warn / skipped when disabled), no placeholder device when the window is missing, and
`Globals` initialization not raising.

Full suite: **215 tests passing** (193 existing + 22 new).
