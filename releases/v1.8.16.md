# v1.8.16 · MuMu 方块改用「落点预览视觉闭环」，不再猜触控坐标 / Rahai Blocks visual servo

本版改了运行时代码，**必须重跑 `python restore.py` 并重启 ok-ww** 才生效。

## 现象

v1.8.12 ~ v1.8.15 连续四版都在修 MuMu 方块拖拽落点，但 x/y 始终对不上：

- v1.8.12 `sendevent` 手算物理坐标 —— 转置当旋转，镜像错位；
- v1.8.14 `input motionevent` —— 走 wm size 竖屏逻辑坐标，与横屏截图错配；
- v1.8.15 MuMu IPC 触控 —— 屏幕坐标语义虽对，实机 xy 仍偏移。

根因是**同一个**：MuMu 的「触控坐标 → 屏幕落点」关系无法靠读代码确定（横竖屏、缩放、镜像都可能因版本/设置不同而变），
继续猜某一套固定映射永远是打地鼠。

## 修复：用游戏自己的落点预览做视觉伺服（不依赖坐标系）

关键观察：拉海洛方块拖拽时会把方块吸附到目标格并显示**高亮落点预览**，
现有 `preview_matches()` 正是靠这个判断能否落子。既然游戏直接把「手指落在哪一格」画了出来，
就直接读它、闭环修正，根本不需要知道触控坐标系：

1. 拖到目标附近后，读预览格子的**包围盒中心**（`preview_center()`，与 `Move.drop` 语义一致，
   L 形方块不会因取格子均值产生半格假偏差）。
2. 用两条正交探针**实测**「手指像素位移 → 预览逻辑位移」的 2x2 雅可比：
   `[[a, c], [b, d]]`，覆盖缩放、轴交换、镜像等任意线性映射。
3. 目标格中心 − 预览中心 = 偏差，用雅可比求逆反推手指该挪多少像素，限幅后移动，
   重复读预览直到 `preview_matches` 命中。
4. 若伺服失败且需要旋转，补转一整圈 90° 再伺服一次，覆盖键位映射偶发丢键。

这一步把「坐标换算」彻底换成「看图反馈」：不管 MuMu 用哪套坐标系、有没有缩放/镜像，
伺服都会实测并自我校正。PC 客户端与云鸣潮仍走原来的坐标路径，不受影响。

## 你需要做的

1. 重跑 `python restore.py`，重启 ok-ww。
2. 保持 v1.8.13 的键位映射（MuMu 里 F1 → 旋转按钮），`Rotate Key (MuMu Keymap)` 仍为 `f1`。
3. 抓屏方式仍建议 IPC（`devices.json` 的 `capture` = `ipc`），保证能稳定读到落点预览。
4. 实机跑一局方块，确认落点命中（本版不做实机验证，由用户自行确认）。
