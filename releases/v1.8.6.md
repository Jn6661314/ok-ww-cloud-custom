# v1.8.6 · 修复重启任务偶尔丢失云鸣潮账号登录态 / Fix cloud login state occasionally lost after task restart

本版改了运行时代码，**必须重跑 `python restore.py` 并重启 ok-ww** 才生效。

## 问题 / The bug

多账号日常运行时，任务出错会自动恢复：`cloud_recovery.refresh_cloud_game()` 调用
`cloud_browser.restart_browser()` 关闭并重新打开云游戏浏览器。但调用处没有传 `account_key`，
而 `restart_browser()` 内部把 `None` 直接当成 `default` 账号，于是：

1. 当前账号（例如 `1351840`）已登录的 profile 被搬回它自己的目录（这一步是对的）；
2. 接着却把磁盘上遗留的 `data/cloud_profiles/default` profile 装进 `cache/playwright`；
3. 新浏览器打开的是 default 登录态（甚至是空目录），表现就是「重启任务后账号掉了」。
   `cloud_browser.json` 的 `active_account` 也被写成 `default`，后续账号跟着错。

在本机实测确实存在 38 MB 的旧 `default` profile，而当前账号目录是刚被
`set_active_account()` 创建的空目录 —— 所以现象是「有时」出现，取决于错误恢复有没有被触发、
以及 default profile 里恰好是谁的登录态。

## 修复 / The fix

- `src/cloud_browser.py` 新增 `resolve_account()`：未显式指定账号时，以**当前 live profile 的
  marker**为准（`cache/playwright/.okww_account`），其次才是 `cloud_browser.json` 的
  `active_account`，最后才是 default。`restart_browser()` 在关浏览器**之前**解析账号，并把
  解析结果传给 `prepare_live_profile()`。
- `save_current()` 同样改为「live 归属优先」：`cloud_launch --account X` 先把 active 写成 X、
  但浏览器里还开着 A 的情况下，不会再误把 A 的 Cookie 快照写进 X 的目录。
- `src/cloud_recovery.py` 的错误恢复显式传 `account_key=cloud_browser.resolve_account()`，
  双保险，不再依赖函数默认值。
- 目录交换不再「锁住就静默删文件」：`_replace_dir()` 改为带退避重试（8 次 × 0.4 s），
  若旧 profile 已挪开但新 profile 装不进去会回滚；始终锁死时直接抛错，避免用半个
  profile 继续启动浏览器。跨盘符仍走复制回退。

## 验证 / Verification

- 新增 `tests/TestCloudRestartLoginState.py` 6 项，覆盖：不传账号重启仍留在当前账号、
  default profile 不受影响、active 落后时按 live 归属保存、profile 被短暂锁住时重试且不删
  Cookie、持续锁住时明确报错、错误恢复显式传账号。用旧版代码跑这 6 项全部失败/报错。
- 全量 **249 项测试通过**（需用 ok-ww 自带解释器）。
- `restore.py` 实跑部署 31 个文件，working / repo 与仓库逐字节一致，
  git HEAD 与版本 tag `v3.8.15` 同为 `36f6034`。

## 使用注意 / Note

修复只对**新启动**的 ok-ww 生效；如果任务正在跑，先停任务、重跑 `restore.py`、再启动程序。
账号登录态本身没有被改动，`data/cloud_profiles/` 下的 profile 全部保留。

---

English summary: error recovery restarted the cloud browser without an account key, so the
code fell back to the `default` profile and appeared to log the active account out. Account
resolution now prefers the live profile marker, recovery passes the account explicitly, and
profile-directory swaps retry on lock instead of silently deleting Cookie files.
