  - `RahaiBlocksTask.py`：以定制版（含 `_go_now_button`、云恢复、浏览器交互）为底，同步删除官方那行 `screenshot("rahai_preview_mismatch")`。
- **更新动作**：repo 快进到官方 `e2cc611`（v3.8.14），官方非冲突文件保持纯官方内容；定制文件写回 working/repo 并同步两套备份；`app.json` 版本 v3.8.13→v3.8.14，复位 update_state。

### 安卓触屏专用操作模式层

- **新增 `src/task/touch_mode.py`（安卓键位模式层）**：把散落在各 task 的 `is_adb()/is_browser()` 判断与触屏键位集中到一处。核心原则：安卓端「返回」和「打开菜单」**是同一个按钮**，就是键位表里的"菜单/跳过"键 `` ` ``（→ `KEYCODE_GRAVE`），不是 `KEYCODE_BACK`（实测主界面发 `KEYCODE_BACK` 弹"是否确定退出游戏"）。`TouchMode` 提供 `is_touch/is_cloud`、`back()/open_menu()`（触屏发 `` ` ``，PC/云维持原 `back()`=esc）、`book_key()`（触屏 F2）。`BaseWWTask` 持有 `self.touch`，PC/云行为零变化。
- **接入点**（`src/task/BaseWWTask.py`）：`is_main(esc=True)` 的返回分支、`open_esc_menu()`（触屏不再做 PC 式 Alt+点击）、`openF2Book()` 的指南书键，均改走 `self.touch`。
- **补全触屏功能键**（`ok/device/interaction_methods/keys.py`）：`ADB_KEY_MAP` 新增 `F1-F12 → KEYCODE_F1..F12`，使触屏指南书 `F2` 合法。

### MCP 端口冲突自适应

- **修复 MCP 服务器开启报 `[Errno 13]`**（`ok/core/mcp_server.py`）：本机百度输入法（`BaiduPinyin.exe`）常驻监听 `0.0.0.0:8765`，OKWW 绑 `127.0.0.1:8765` 时 Windows 返回 `EACCES(13 / winerror 10013)`，而非通常的 `EADDRINUSE(10048)`；原 `bind_mcp_socket` 只认后者，直接把 EACCES 抛出，GUI 弹"MCP 服务器错误"。现把 `EACCES/10013` 一并视作端口冲突，自动递增到可用端口（实测 8765 冲突→8766 绑定成功）。实际端口经 `getsockname()` 写回 connection 文件，客户端动态发现，无需改配置、也无需关闭输入法。

### MuMu 模拟器窗口化操作（PC 式输入）

- **问题本质**：MuMu 模拟器就是一个 Windows 窗口，用户已在模拟器里把游戏键位映射配好。而 OKWW 对 adb 设备固定用 `ADBInteraction`（`input keyevent`/`input tap`）——这是直接给安卓系统发按键，**完全绕过模拟器的键位映射**：`KEYCODE_BACK` 在主界面弹"是否确定退出游戏"、键位表里的 `` ` ``（菜单/跳过）从未生效。正确做法是与 PC 客户端/云游戏一致：向模拟器窗口发真实键盘/鼠标消息，由模拟器键位映射转成游戏操作。
- **框架改动**（`ok/device/DeviceManager.py`）：`do_start` 的 adb 分支原本无条件强制 `ADBInteraction`，现尊重显式配置的 interaction（`config['interaction']` + `win_interaction_class`，且需 `hwnd_window` 存在），未配置时保持原行为，对其他用户零影响。
- **配置改动**（`config.py` adb 段）：`capture_method: 'windows'`（MuMu 窗口截图，走 WGC）+ `interaction: 'PostMessage'`。键盘按键经 `vk_key_dict`/`VkKeyScan` 转 VK 码 PostMessage 给 MuMu 窗口；鼠标点击由 MuMu 转成触屏 tap。
- **连带修复**：`MouseResetTask` 在 adb 下每 10 秒刷的 `'ADBCaptureMethod' object has no attribute 'get_abs_cords'` 随截图通道切到 PC 侧而消失（`BaseCaptureMethod` 本有该方法）。

### Full update to official v3.8.14 (ok-script 3.0.13 WebRTC)

- **Official new features**: cloud capture changed from "screenshot the browser window (WGC)" to "read the game video stream directly (WebRTC)", so screenshots work even when the browser is minimized; restarting after a browser start failure no longer requires restarting ok-ww; task errors now save a screenshot to `screenshots/error/`; a mismatching Rahai Blocks landing preview no longer screenshots every time. The official change touches 13 files (including the new `ok/device/capture_methods/browser_webrtc.py`).
- **Conflict analysis**: 3 of those 13 files overlap with the customizations — `config.py`, `ok/device/capture_methods/browser.py`, and `src/task/RahaiBlocksTask.py`. The official `browser.py` changed 182 lines and added the WebRTC module while the customization changed 87 lines (Cookie/account profile, background input disguise, UID cover); the automatic three-way merge failed, so the official new version was used as the base and each customization was ported over by hand.
- **Merge result**:
  - `browser.py`: 100% of the official WebRTC code is preserved, with 5 customizations ported over (two JS constants, per-account user_data_dir, storage_state restore + background/UID init scripts, page evaluate reuse, storage_state save). The only difference from the official new version is the 5 added blocks; no official code was removed.
  - `config.py`: based on the official v3.8.14 version, keeping the official `'capture': 'webrtc'` while re-adding custom_tabs, the adb section, user_data_dir, nick, and the cloud multi-account task list.
  - `RahaiBlocksTask.py`: based on the custom version (with `_go_now_button`, cloud recovery, browser interaction), with the official `screenshot("rahai_preview_mismatch")` line removed.
- **Update actions**: the repo fast-forwarded to official `e2cc611` (v3.8.14); non-conflicting official files stay pure official; the custom files were written back to working/repo and both backup sets synced; `app.json` version bumped v3.8.13→v3.8.14 with update_state reset.
- **Note**: WebRTC capture looks different from the old WGC one (only the video stream is captured, with black around page elements). If anything goes wrong, change `'capture': 'webrtc'` back to `'wgc'` in `config.py` and restart (the background disguise still works).

### Dedicated Android touch operation mode layer

- **New `src/task/touch_mode.py` (Android key mode layer)**: the scattered `is_adb()/is_browser()` checks and touch key bindings across tasks are centralized in one place. The core principle: on Android, "go back" and "open menu" **are the same button** — the "menu/skip" key `` ` `` in the key table (→ `KEYCODE_GRAVE`) — not `KEYCODE_BACK` (which, when sent on the main screen, pops up "are you sure you want to quit the game?"). `TouchMode` provides `is_touch/is_cloud`, `back()/open_menu()` (touch sends `` ` ``, PC/cloud keep the original `back()` = esc), and `book_key()` (touch F2). `BaseWWTask` holds `self.touch`; PC/cloud behaviour is unchanged.
- **Integration points** (`src/task/BaseWWTask.py`): the return branch of `is_main(esc=True)`, `open_esc_menu()` (touch no longer does the PC-style Alt+click), and the guidebook key in `openF2Book()` all route through `self.touch`.
- **Complete the touch function keys** (`ok/device/interaction_methods/keys.py`): `ADB_KEY_MAP` gained `F1-F12 → KEYCODE_F1..F12`, making the touch guidebook `F2` legal.

### MCP port conflict adaptation

- **Fixed the MCP server failing with `[Errno 13]`** (`ok/core/mcp_server.py`): the local Baidu IME (`BaiduPinyin.exe`) permanently listens on `0.0.0.0:8765`; when OKWW binds `127.0.0.1:8765` Windows returns `EACCES(13 / winerror 10013)` instead of the usual `EADDRINUSE(10048)`. The old `bind_mcp_socket` only recognized the latter and rethrew the EACCES, so the GUI showed an "MCP server error". Now `EACCES/10013` is also treated as a port conflict and the port increments automatically until one is free (measured: 8765 conflicted → 8766 bound successfully). The actual port is written back to the connection file via `getsockname()` so clients discover it dynamically — no config change and no need to close the IME.

### MuMu emulator windowed operation (PC-style input)

- **The real problem**: the MuMu emulator is just a Windows window, and the user has already configured the key bindings inside it. Yet OKWW hard-codes `ADBInteraction` (`input keyevent` / `input tap`) for adb devices — that sends keys straight to the Android system and **completely bypasses the emulator's key mapping**: `KEYCODE_BACK` pops "are you sure you want to quit the game?" on the main screen, and the `` ` `` (menu/skip) key in the key table never worked. The correct approach matches the PC client and cloud mode: send real keyboard/mouse messages to the emulator window and let the emulator's own key mapping turn them into game input.
- **Framework change** (`ok/device/DeviceManager.py`): the adb branch of `do_start` used to unconditionally force `ADBInteraction`; it now respects an explicitly configured interaction (`config['interaction']` + `win_interaction_class`, and requires `hwnd_window` to exist). Without configuration the old behaviour is kept, so other users see zero impact.
- **Configuration change** (the `adb` section of `config.py`): `capture_method: 'windows'` (MuMu window capture via WGC) + `interaction: 'PostMessage'`. Keyboard keys are converted to VK codes via `vk_key_dict`/`VkKeyScan` and posted to the MuMu window; mouse clicks are converted by MuMu into touch taps.
- **Side fix**: the `'ADBCaptureMethod' object has no attribute 'get_abs_cords'` that `MouseResetTask` printed every 10 seconds on adb disappeared once the capture channel moved to the PC side (`BaseCaptureMethod` already had that method).
