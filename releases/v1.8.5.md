# v1.8.5 · 两套 Agent 安装提示词：云鸣潮定制 / 真双机版

本版只改文档与安装引导，不改任何运行时代码，无需重新跑 `restore.py`。

## 背景

用户问能否把 [xueyuannnn/okww-dualpc](https://github.com/xueyuannnn/okww-dualpc) 的「真双机」做成
本定制分支的同款功能。评估结论是**不做合并**，改为维护两套独立安装：

| 维度 | 本仓库定制补丁 | okww-dualpc 双机版 |
| --- | --- | --- |
| 场景 | 云鸣潮 / 多账号 / MuMu / 远控窗口 / 单机 PC | 游戏机 + 控制机，采集卡取画面，KMBox Net 键鼠盒或 SendInput 输入 |
| 技术栈 | Python（ok-ww 3.8.15 + ok-script 3.0.14） | Rust 业务内核 + Qt/C++ 界面 + Python 工坊，基线是 ok-ww-enhanced 与 ok-script 2.0.8+dualpc.1 |
| 代码量 | 31 个文件 | `dualpc/` 41 个 Python 文件约 6624 行（还有 Rust/C++），仅设备/任务适配层 |
| 设备层 | 修改现有 `DeviceManager`，多种设备共存 | `DualPCDeviceManager` 把 `device_dict` 覆写成唯一 `dualpc`，并关闭 browser/adb/windows，天然互斥 |
| 配置 | `config.py::global_configs` + `configs/` | 独立 `dualpc.json` + 自定义 `DualPCTab` |
| 安装 | 覆盖现有 ok-ww 的 `working`/`repo` | 独立目录，环境包 + 累计增量包合并解压 |

移植需要把 6600 行跨基线适配到我们不同的 `config.py` / 任务集，再自行补 DXGI 桌面复制和 Qt 页面，
工作量和回归风险都远大于「直接安装它的官方包」。两套独立安装还能各自升级、互不影响。

## 新增内容

- **`AGENT_INSTALL_DUALPC.md`（新）**：双机版安装提示词，自包含、可直接复制给 Agent：
  - 先读上游 README 顶部取当前环境包 + 累计增量包链接（不写死版本号）；
  - 两个 ZIP 里的 `OKWW-DualPC-full` **合并解压到同一目录**，避免多套一层；
  - 检测采集卡（NV12）/ DXGI 单机或远程、KMBox Net（地址/端口/UUID）或 SendInput，测试移动；
  - F9 全局暂停、托盘退出、更新时备份 `native-full-data/`；
  - 明确禁止改动现有 ok-ww 的 `restore.py`、`app.json`、`working`/`repo`；
  - Windows 10/11 x64 限制与 AGPL-3.0 提醒。
- **`AGENT_INSTALL_PROMPT.md`**：顶部加分流规则（云鸣潮/MuMu/远控 → 本文件；双机/采集卡/KMBox → 新文件）。
- **`README.md`**：「让 Agent 帮你安装：先选对版本」表格 + 不合并的理由；顺手修正两处过时的
  `Done: 15/29 file copies` 文案（现为 31 个文件 × 2 目录 = 62，且数字随清单变化，以脚本实际输出为准）。

## 测试 / 验证

无运行时代码变更。全量 **243 项测试**仍通过。

## 升级

无需操作；只有当你需要双机版时，用 `AGENT_INSTALL_DUALPC.md` 做一次独立安装。

# v1.8.5 · Two Agent install prompts: cloud-custom / true dual-PC

Documentation-only release. No runtime code changed; no need to re-run `restore.py`.

## Why two installs instead of porting the dual-PC feature

We evaluated [xueyuannnn/okww-dualpc](https://github.com/xueyuannnn/okww-dualpc). Its "true dual-PC"
mode (capture card + KMBox Net hardware input) is a **complete separate implementation**: Rust core,
Qt/C++ UI, and ~6,600 lines of Python adapters on a different upstream (ok-ww-enhanced, ok-script
2.0.8+dualpc.1). Its `DualPCDeviceManager` replaces `device_dict` with a single `dualpc` device and
disables browser/adb/windows — mutually exclusive with our cloud / MuMu / remote-window devices.
Porting it would mean re-basing thousands of lines onto our different `config.py` and task set, plus
reimplementing DXGI capture and Qt pages. Installing its official package in a separate directory is
simpler, safer, and upgradable independently.

## Added

- **`AGENT_INSTALL_DUALPC.md`**: self-contained install prompt for the dual-PC edition — reads current
  environment + cumulative update links from upstream README, merges both ZIPs into one directory,
  configures capture card (NV12) / DXGI and KMBox Net / SendInput, covers F9, tray exit, config backup
  on update, Windows 10/11 x64 only, AGPL-3.0, and an explicit "do not touch your existing ok-ww install".
- **`AGENT_INSTALL_PROMPT.md`**: routing note at the top (cloud/MuMu/remote → this file; dual-PC/capture
  card/KMBox → the new file).
- **`README.md`**: selection table plus rationale; fixed two stale `Done: 15/29 file copies` messages
  (now 31 files × 2 directories = 62, with a note that the number tracks the file list).

## Tests / upgrade

No runtime changes; all **243 tests** still pass. Nothing to do unless you want the dual-PC edition —
in that case use `AGENT_INSTALL_DUALPC.md` for a separate install.
