# v1.5.8 · 修复 MuMu 打着打着停 / 按编队识别队伍 / AutoCombatTask 兼容 / Fix MuMu mid-combat stall, formation-based team detection and AutoCombatTask compatibility

## 中文

### 问题现象

v1.5.7 解决了“完全不会打”：MuMu 能自动锁敌、攻击和放技能了。但继续运行会出现新问题：

- 打着打着突然不出招，自动战斗像“自己关掉了一样”；
- 队伍识别不对：明明是完整三人编队，脚本却按两人队伍加载；
- 当前角色按默认 1 号位算，实际可能是 3 号位；
- 切人也可能切错：MuMu 键位映射里的“切换角色 1/2”与编队槽位不一定是 `index + 1` 的直连关系。

### 根因

1. **`in_team_android()` 写死 2 人队伍、当前角色默认 1 号位**  
   截图里右上角其实有两个非出战角色徽章 `1`、`2`，这代表完整三人编队，且当前出战的是 3 号位。  
   但代码固定 `return True, current_index, 2`，`load_chars()` 随后把第三人裁掉，工坊编队代码也永远不会被应用。
2. **切人键写死 `index + 1`**  
   实测截图里徽章 `1` 旁边的键位提示是“切换角色 2”，徽章 `2` 旁边是“切换角色 1”。  
   照 `index + 1` 发键会切到错误角色，导致角色逻辑和实际画面错开。
3. **AutoCombatTask 没有 BaseCombatTask 的 None 守卫**  
   `BaseCombatTask.combat_once()` 早就在当前角色为空时重载重试，但触发任务 `AutoCombatTask.run_auto_combat()` 仍直接 `get_current_char().perform()`。  
   MuMu 切人动画/HUD 抖动时角色对象会短暂全部为空，这里抛 `AttributeError`，TaskExecutor 把普通异常当作任务故障并 disable 触发任务——表现就是自动战斗打着打着自己停了。
4. **手游血条闪烁没有宽限**  
   云游戏有 `cloud_health_bar_grace()` 容忍压缩/特效造成的短暂血条丢失，但安卓端没有。血条一闪就会误判目标丢失、退出战斗。

### 修复（PC / 云游戏行为不变）

- **按编队识别队伍**：新增手游队伍栏 OCR（`1/2/3` 徽章 + “切换角色N”提示，0.3 秒缓存）：
  - 两个徽章 → 三人队；缺的槽位就是当前出战角色；
  - OCR 读不到时按完整三人编队加载，并保留脚本维护的 `_android_current_index`，不再粗暴重置为 0；
  - 队伍人数不再写死 2，`load_chars()` 能加载第三人和对应工坊角色代码。
- **按键位提示切人**：新增 `android_switch_key(index)`；安卓端优先用 OCR 读出的“徽章→切换键”映射，PC / 云仍用原来的 `index + 1`。
- **AutoCombatTask 兼容 MuMu**：
  - 新增 `_current_char_for_perform()`，当前角色为空时安卓端重载一次再取，仍为空则下一帧重试；
  - 捕获 perform 期间的普通异常，记录日志并 `reset_auto_combat()`，不再让 TaskExecutor 关闭触发任务；
  - 新增 `src/task/AutoCombatTask.py` 覆盖层并加入 `restore.py` 部署清单。
- **安卓血条宽限**：`cloud_health_bar_grace()` 同时覆盖 `is_browser()` 和 `is_adb()`，血条短暂闪烁不再立刻退出战斗。

### 验证

### 建议验证方式

1. 保持 v1.5.7 的 MuMu 键位映射不变（`Y` 锁敌，技能键，WASD 移动）。
2. 启动任务后观察队伍栏：脚本应识别为三人队，当前角色按缺失徽章推断。
3. 切人时应切到预期角色；自动战斗即使中途角色对象抖动也会重载重试，不再自己关闭。
4. 若键位提示与编队槽位关系和截图不同，本版会按实际 OCR 到的“切换角色N”自动适配。

## English

### Symptom

v1.5.7 fixed "never fights": MuMu could lock on, attack and use skills. Continued runs then showed a new problem:

- Combat suddenly stopped as if auto combat had disabled itself;
- Team detection was wrong: a full three-member formation was loaded as two characters;
- The active character was assumed to be slot 1 while it could actually be slot 3;
- Switching could target the wrong slot because MuMu's "switch character 1/2" keymap labels are not always `index + 1`.

### Root cause

1. **`in_team_android()` hard-coded a 2-member team and slot 1 as active**  
   The screenshot shows two non-active badges `1` and `2` on the upper-right party bar, which means a three-member team with slot 3 active.  
   The code still returned `return True, current_index, 2`; `load_chars()` then dropped the third character and never applied its workshop code.
2. **Switch key hard-coded to `index + 1`**  
   In the screenshot, badge `1` is labelled "切换角色 2" and badge `2` is labelled "切换角色 1". Sending `index + 1` switches to the wrong character and desynchronises the script from the game.
3. **AutoCombatTask lacked BaseCombatTask's None guard**  
   `BaseCombatTask.combat_once()` already reloads when the current character is missing, but the trigger task `AutoCombatTask.run_auto_combat()` still called `get_current_char().perform()` directly. On MuMu, character objects can briefly all be None during switching/HUD changes; that `AttributeError` made TaskExecutor disable the trigger task — "auto combat stopped by itself".
4. **No grace for mobile health-bar flicker**  
   Cloud mode had `cloud_health_bar_grace()`, but Android did not; a single flicker could end combat.

### Fix (PC / cloud behavior unchanged)

- **Formation-based team detection**: added OCR of the mobile party bar (`1/2/3` badges plus "切换角色N" hints, cached for 0.3s):
  - two badges mean a three-member team; the missing slot is active;
  - when OCR finds nothing, still load the full three-member team and keep `_android_current_index` instead of resetting it;
  - team size is no longer hard-coded to 2, so the third character and workshop code are loaded.
- **Keymap-based switching**: added `android_switch_key(index)`; Android uses the OCR-derived badge→key mapping, PC/cloud keep `index + 1`.
- **AutoCombatTask MuMu compatibility**:
  - added `_current_char_for_perform()` to reload once on Android and retry next tick if still empty;
  - catch ordinary exceptions during perform, log them and call `reset_auto_combat()` instead of letting TaskExecutor disable the trigger task;
  - added `src/task/AutoCombatTask.py` override and registered it in `restore.py`.
- **Android health-bar grace**: `cloud_health_bar_grace()` now applies to both `is_browser()` and `is_adb()`.

### Verification

- New `tests/TestAndroidTeamFormation.py`: 9 tests all green (two badges = three-member team, missing badge sets active slot, no badges keeps full team, reversed keymap, PC switch key unchanged, AutoCombatTask None guard, deploy manifest, health grace).
- Regression all green: `TestAndroidCombatFix` 13, `TestAndroidDisconnect` 7, `TestAndroidKeymapCombat` 15, `TestAndroidMouseHold` 8, `TestAndroidTargetKey` 13, `TestCloudCombatFixes` 4.
- `restore.py` deployed 33 custom files to working + repo; hashes match across source/working/repo for all five core modified files, compilation passes.

### Suggested check

1. Keep v1.5.7's MuMu keymap unchanged (`Y` target lock, skill keys, WASD movement).
2. After starting, the script should treat the party as three members and infer the active slot from the missing badge.
3. Switching should land on the expected character; if character objects flicker, auto combat retries instead of disabling itself.
4. If your keymap labels differ from the screenshot, this version adapts to the OCR-detected "switch character N" hints automatically.
