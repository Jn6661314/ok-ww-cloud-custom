# v1.5.9 · 修复 MuMu 无法谐振破坏 / Fix MuMu unable to trigger Resonance Break

发布日期 / Date: 2026-11-25

## 问题 / Problem

- **中文**：MuMu/安卓端自动战斗从不触发谐振破坏（敌人破防后的大伤害一击）。
- **English**: On MuMu/Android auto combat never triggered Resonance Break (the heavy strike when an enemy's tune gauge breaks).

## 根因 / Root Cause

- **中文**：PC 端 `f_break` 模板是 **"F" 键帽图标**（36×43，取自 3840×2160 PC 截图）。手游端的谐振破坏提示是**触摸图标 + 文字**，PC 模板永远匹配不上 → `check_f_break()` 恒 False → `f_break()` 从不执行。即使偶发识别到，旧动作也是 `send_key('f')`，手游端按 F 并不触发谐振破坏。
- **English**: The PC `f_break` template is the **"F" keycap icon** (36×43, cropped from a 3840×2160 PC screenshot). The mobile prompt shows a **touch icon + text** instead, so the template never matches → `check_f_break()` always False → `f_break()` never runs. Even if detection had worked, the old action `send_key('f')` does nothing on mobile — the prompt must be tapped.

## 修复 / Fix

全部在 `src/combat/CombatCheck.py`，PC / 云游戏行为不变。/ All in `src/combat/CombatCheck.py`; PC/cloud behavior unchanged.

### 中文

- **安卓端检测改为两层**（`_android_check_f_break()`）：
  1. `f_break_full` 谐振条满图标模板（跨端美术一致），阈值 0.92 → **0.85**；
  2. OCR 在屏幕中央区域（20%~75%）识别"**破坏 / 谐振**"提示文字，识别成功把文字位置存入 `_f_break_box`。
  - OCR 有开销，限制 **1 秒一次**；`f_break_full` 模板便宜，每次调用都查（与 PC 相同）。
- **安卓端动作改为点击提示位置**：`f_break()` 在安卓端直接 `click(box.center())` 点识别到的图标/文字本身；识别不到坐标但 `can_break` 被其它路径置位时，降级为普攻 + F 尽力而为。
- OCR 失败安全兜底：异常只记录 debug 日志，不影响战斗循环。
- 退出战斗时 `_f_break_box` 一并清理，避免残留坐标误点。
- PC/云游戏仍走原路径：`f_break_full`(0.92) → 1 秒节流的 `f_break` 模板 + `is_pick_f()` 拾取消歧 → `send_key('f')` + 普攻。

### English

- **Two-layer Android detection** (`_android_check_f_break()`):
  1. `f_break_full` tune-gauge icon template (identical art across platforms), threshold 0.92 → **0.85**;
  2. OCR over the central screen area (20%–75%) for the "**破坏 / 谐振**" (Break) prompt text; on a hit the text position is stored in `_f_break_box`.
  - OCR is throttled to **once per second**; the cheap `f_break_full` template runs on every call (same as PC).
- **Android action taps the prompt itself**: `f_break()` on Android clicks the detected icon/text position (`box.center()`); if `can_break` was set elsewhere without a box, it falls back to attack click + F as a best effort.
- OCR failures are logged at debug level only and never break the combat loop.
- `_f_break_box` is cleared when combat resets, preventing stale-position misclicks.
- PC/cloud keep the original path: `f_break_full` (0.92) → throttled `f_break` template + `is_pick_f()` disambiguation → `send_key('f')` + attack.
