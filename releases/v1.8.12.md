# v1.8.12 · MuMu 拉海洛方块真双指触控 + 不再要求窗口前台 / MuMu Rahai Blocks: two-finger touch, no foreground required

本版改了运行时代码，**必须重跑 `python restore.py` 并重启 ok-ww** 才生效。

> 附带的「必须在前台」问题也一并解决：MuMu 改回 IPC 抓屏（从模拟器内部取帧，
> 不依赖窗口前台）+ 双指触控走 sendevent 直写触控设备（也不需要前台），
> 现在 MuMu 窗口可以在后台，方块任务照常跑。

## 现象

MuMu 下拉海洛方块玩不了。日志报：

```
RahaiBlocksTask:_place line 482 → move_cursor line 478
AttributeError: 'NemuIpcCaptureMethod' object has no attribute 'get_abs_cords'
```

## 根因（三层）

1. **v1.8.11 的回归**：为修「MuMu 连不上」，我把 `devices.json` 的 `capture` 从 `windows` 纠偏成了 `ipc`。而方块的拖拽走 Pynput，需要 `capture.get_abs_cords()`（只有 windows 抓屏有），IPC 抓屏没有 → 崩溃。
2. **更根本的问题**：手游版旋转靠屏幕左侧的圆形「旋转」按钮，玩家操作是**一指点旋转按钮 + 另一指长按拖动方块**（真双指）。原代码用「拖动 + 键盘 R」，依赖 MuMu 键位映射把 R 转成旋转点击——但手游不认键盘 R，键位映射没配就转不了。而 MuMu IPC SDK（`nemu_input_event_touch_down/up`）和 uiautomator2 的 touch API 都是**单指**（pointer id 固定 0），做不了双指。
3. **"必须在前台"**：为了让 get_abs_cords 可用而退回的 `windows` 抓屏里，BitBlt 明确标了 `foreground only`、`is_foreground()` 检查——MuMu 窗口一离开前台就抓不到画面，任务被迫一直占着前台。

## 修复

1. **输入彻底脱离抓屏**：方块输入改用 sendevent 双指后，不再需要 `get_abs_cords`，也不会因为键盘 R 依赖键位映射。于是抓屏可以安全用回 **IPC**（从模拟器内部取帧，不依赖窗口前台），**「必须在前台」随之解决**——MuMu 可以放后台。同时保留 v1.8.11 修的 `resolve_emulator_window_exe()`（windows 抓屏拿启动器 exe 找不到 hwnd 的「连不上」问题）。`available_capture_methods()` 也把 `windows` 列为模拟器合法抓屏方式之一（用户手动选窗口抓屏时不再被纠偏）。
2. **新增真双指触控**（`src/task/multi_touch.py`）：直接通过 ADB `sendevent` 写 Linux input 子系统的 `ABS_MT_SLOT` 多点触控协议——
   - 触控设备自动探测（支持 `ABS_MT_SLOT` 的 Touchscreen 节点，本机为 `/dev/input/event4`）；
   - **slot 0** = 拖动方块的手指（down / move / up）；
   - **slot 1** = send_key('r') 时点屏幕旋转按钮（不干扰 slot 0 的拖动）；
   - 坐标映射：物理屏 1080×1920 竖屏、游戏横屏，实测映射为 `物理(x,y) = (游戏y, 游戏x)`；
   - 任务中断时 `on_destroy()` 释放所有仍按下的触点，避免"手指卡住"。
3. `RahaiBlocksTask._make_interaction()`：adb 设备改用 `MuMuMultiTouchInteraction`；`_clickable()` 在 adb 下恒 True（sendevent 不要求窗口前台）。

## 验证

- 新增 `tests/TestMuMuMultiTouch.py` 15 项（坐标映射、slot/tracking_id 管理、send_key('r') 用 slot 1 点旋转按钮、旋转不打断拖动、异常释放触点）+ 更新方块无尽模式测试 2 项。
- 全量 **225 项通过**（ok-ww 自带 Python）。
- 真实设备验证：触控节点 `/dev/input/event4` 自动识别、sendevent 双指协议实测点中旋转按钮（画面差异 86.5）、模块端到端执行后触点正确释放。
