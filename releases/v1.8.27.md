## 一、基线：v3.8.15 → v3.8.18

上游这三个版本动的地方不多，但每一处都正好压在定制层上，所以不是简单覆盖：

| 上游的东西 | 冲突在哪 | 怎么合的 |
| --- | --- | --- |
| 新增 `child_session`（在 Windows 子会话里跑游戏，任务不抢你的鼠标键盘） | 我们改过 `config.py` 的整块配置字典 | **两个都留**：`child_session` 和我们的 `adb`（MuMu/安卓入口）并存，互不干扰 |
| `USE_ECHO_BOX_FOR_DAILY` + `DailyTask._read_daily_points()` | 我们把每日任务的点数读取整段换成了宽区域重试 | **先走上游的**，失败再回退我们的宽区域重试——上游正常运行时用上游的，云游戏糊屏时才走我们的 |
| `BaseCombatTask` 安卓逻辑序号 + `already_switched` 判断 | 两边都改了切人逻辑 | 把我们的"逻辑序号 → 物理位"映射并进上游的 `already_switched` 守卫里，不重复切 |
| `rahai_blocks.py` 注释改成英文 | 我们在这文件里有改动 | 采用上游的英文注释（上游是给国际社区看的） |
| `CombatCheck` 新增 `ChildSessionInteraction` | 我们动了 `GetCursorPos/SetCursorPos` 那段 | 子会话下宿主光标**不动**（`on_host` 判断），只在非子会话时才存/设宿主光标 |

另外 `version` 从 `v3.8.15` 提到 `v3.8.18`，`restore.py` 的版本 tag 也跟着钉到了新的定制提交。

## 二、上游评审指出的 7 个问题

`ok-oldking` 在三个 PR（#1881 拉海洛无尽模式 / #1882 梦魇聚落锁敌重试 / #1883 多账号云游戏）
里各提了评审意见，逐条修完后重新对照了他的原话。7 条都在这一个版本里落地：

### 1. 看不到敌人 ≠ 敌人飞走了（锁敌重试白等）

原来只要"这一帧没识别到敌人"就进重锁重试，可**打死清场**的时候本来就没敌人。
后果是白等 `重试次数 × 超时` 秒，还会把 `target_lost_give_up` 置真，
让任务误判"目标丢失"去跳过聚落、跳过找声骸。

现在要求**正向证据**：`has_health` 为假（一个血条都看不到）直接返回，
不重试；ADB 端、`重试次数 <= 0` 也直接返回。

### 2. 跳过聚落时把残象一起丢了

`_skip_nest_after_target_lost()` 在找残象之前就 `return` 了，白丢一个声骸；
而且没有记录"这个聚落打不了"，下一个循环又传送回来，来回死在同一个聚落。

现在：先把聚落记进 `_unreachable_nests`，**然后照常找残象**；顺手把找残象抽成
`_find_echo()`（走近 → 识别 → 必要时重新传送），"目标丢失"和"正常清场"两条路共用。

### 3. 无尽模式判定靠"棋盘可玩"反推

`_endless_ingame()` 之前返回 `bool(self._playable_board())`——但**普通关卡同样有可玩的棋盘**，
于是普通关卡被判成无尽模式。现在只认弹窗/无尽界面这两个正则；
`run()` 里补了 `_endless_page()` 分支（列表页 → 进无尽），`_return_to_list()` 改成
3 次尝试，不再一次不成就卡死。

### 4. 多账号云模式没隔离任务配置，任务被停掉整轮失败

每个账号跑之前没有隔离任务配置，上一个账号的改动会漏到下一个；
用户在界面上点了停止（`TaskDisabledException`）会被当成"这一轮失败"。

现在 `_run_cloud()` 包在 `isolated_task_configs(...)` 里，捕获 `TaskDisabledException`
记成 `'cancelled'`、界面显示"已停止"，其余账号照常继续。

### 5. 换 profile 目录时 EXDEV 回退会"删了旧的又没铺上新的"

`_replace_dir()` 跨盘（`EXDEV`）时先删目标再 `copytree`，中途失败就两边都没了 ——
而这里装的是**登录态**，丢了就得重新扫码。

现在先把目标挪到 `retired`，`copytree` 失败就**回滚**把 `retired` 挪回来，
只有成功后才删 `retired`。

### 6. 设备还没解析出来时，云游戏按钮就不见了

`_is_cloud_device()` 原来只看 `get_preferred_device()`，而界面首帧设备还没解析完，
于是云模式的多账号按钮一闪而过。

现在 `get_preferred_device()` 取不到时回落到已保存的 `config['preferred']`，
首帧就能判对。**只有 `browser` 才算云游戏**，PC 用户（`windows`）不会多出云按钮。

### 7. "取不到账号"和"只登录"混成一个分支

`_run_cloud_account()` 里 `account is None`（账号取不到）和 `task is None`（只登录）走了同一段，
结果是**账号丢了也显示"登录成功"**，问题被盖住。

现在分开：`account is None` → 走日常任务并报明原因；`task is None` → 只登录。

## English summary

This release does two things.

**Code.** The custom layer is rebased onto official **v3.8.18** (previously v3.8.15). Upstream's new
`child_session` (run the game in a Windows child session so tasks never touch your mouse) now
coexists with our `adb` entry; `DailyTask` prefers upstream's `_read_daily_points()` and only falls
back to our wide-region retry; `BaseCombatTask` merges our logical-slot mapping with upstream's
`already_switched` guard; `CombatCheck` leaves the host cursor alone under `ChildSessionInteraction`.

**The 7 review findings** from `ok-oldking` (#1881 / #1882 / #1883) are all fixed:
(1) target-lock retry now requires positive evidence (`has_health`) — no retry when the enemy is
simply dead; (2) skipping an unreachable nest still searches for the echo and records the nest in
`_unreachable_nests`; (3) endless-mode detection relies only on the popup/endless-screen regexes
instead of `_playable_board()`, plus an `_endless_page()` branch and a 3-attempt `_return_to_list()`;
(4) cloud multi-account runs inside `isolated_task_configs()` and treats `TaskDisabledException` as
`cancelled` instead of failing the whole round; (5) the `EXDEV` fallback in `_replace_dir()` moves
the target aside and rolls back on failure instead of deleting the login state first;
(6) `_is_cloud_device()` falls back to the saved `preferred` while the device is still resolving;
(7) "no account" and "login only" are handled as separate cases.

**Distribution.** For the first time there is a **ready-to-run archive**: `ok-ww-custom-v1.8.27-full.7z`
contains the official launcher, the full `data/apps/ok-ww/` tree **including a bundled Python 3.12
environment**, the v3.8.18 source with our patch (git tag pinned so the launcher cannot revert it),
a green layout where `ok-ww.exe` sits next to `data/` — the launcher resolves all paths relative
to its current working directory, so double-clicking the exe just works (no installer, no registry
writes, nothing copied to `%LOCALAPPDATA%`) — and a Chinese README. It contains **no** `configs/`, accounts, cookies, `cloud_profiles/`, logs, screenshots or the
`nectarlink` device identity — verified twice at packaging time.

Python test suite: **481 tests, all passing**. No in-game verification was done for this release,
by prior agreement.
