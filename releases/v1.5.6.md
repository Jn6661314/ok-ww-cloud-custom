# v1.5.6 · 修复 MuMu 重击长按崩溃 / Fix MuMu crash on heavy attack

## 中文

### 问题现象

v1.5.5 修好掉线弹窗后，程序能正常启动、角色也能识别，但自动战斗**一开打就报错停止**。
日志堆栈：

```
Rover: perform_spectro_routine -> spectro_routine_aftertune_combo -> heavy_attack
BaseChar.py:924  self.task.mouse_down()
AttributeError: 'ADBInteraction' object has no attribute 'mouse_down'
TaskExecutor: ⚔️ Auto Combat exception stopped
```

这是"战斗真正跑起来后"才暴露的下一层问题：前几轮修复让角色进入了攻击循环，
漂泊者的重击连招第一次执行到 `heavy_attack()`（长按普攻 0.6 秒）就崩了。

### 根因：ADB 交互层缺少 mouse_down/mouse_up

`heavy_attack()`（`BaseChar.py`）用 `mouse_down()` + sleep + `mouse_up()` 实现长按普攻，
这个模式在 **20+ 个角色类**的重击连招里都用（Camellya、Changli、Phoebe、Rover 等）。
而上游 `ADBInteraction` 只实现了 `click/send_key/swipe`，**没有 `mouse_down/mouse_up`**
（这两个方法只在 PC 的 PostMessage / 浏览器 / Genshin 交互类里有）。
所以 MuMu 走 ADB 通道时，任何重击连招都会抛 `AttributeError` 中断整个自动战斗。

### 修复（BaseWWTask 覆盖层，PC/云游戏行为不变）

在 `BaseWWTask` 覆盖 `mouse_down/mouse_up`（在部署清单内，所有任务都继承它），
一处修复覆盖全部角色的重击调用：

- **安卓端**：`mouse_down()` 把 `-1,-1` 解析为屏幕中心（与本类 `click()` 对普攻的处理一致），
  用 `nemu_impl.down(x,y)` 触摸按下；`mouse_up()` 用 `nemu_impl.up()` 抬起。
  无 nemu 通道或调用失败时降级为一次普通 `click()`，保证战斗循环不因异常中断。
- **PC / 云游戏**：`is_adb()` 为 False 时直接 `super()` 走上游实现，行为完全不变。

### 验证

- 新增 `tests/TestAndroidMouseHold.py` 8 项全绿：adb 中心长按、显式坐标、down/up 配对、
  无前置 down 空操作、nemu 失败降级、无 nemu 降级、PC/云走 super、覆盖 20+ 角色调用点
- 回归：`TestAndroidDisconnect` 7、`TestAndroidTargetKey` 13、`TestAndroidCombatFix` 13、
  `TestCloudCombatFixes` 4 全部通过
- 已部署到 working + repo，三处哈希一致、编译通过

## English

### Symptom

After v1.5.5 fixed the disconnect dialog, the program started normally and characters were
recognized — but auto-combat **crashed as soon as it began**. Stack trace:

```
Rover: perform_spectro_routine -> spectro_routine_aftertune_combo -> heavy_attack
BaseChar.py:924  self.task.mouse_down()
AttributeError: 'ADBInteraction' object has no attribute 'mouse_down'
TaskExecutor: ⚔️ Auto Combat exception stopped
```

This is the next-layer issue exposed only once combat actually runs: earlier fixes got the char
into the attack loop, and Rover's heavy-attack combo crashed the first time it called
`heavy_attack()` (hold normal attack for 0.6s).

### Root cause: ADB interaction layer lacks mouse_down/mouse_up

`heavy_attack()` (`BaseChar.py`) implements a held normal attack via
`mouse_down()` + sleep + `mouse_up()`, a pattern used in **20+ character classes'** heavy combos
(Camellya, Changli, Phoebe, Rover, etc.). Upstream `ADBInteraction` only implements
`click/send_key/swipe` — **no `mouse_down/mouse_up`** (those exist only in the PC PostMessage /
browser / Genshin interaction classes). So on MuMu's ADB channel, any heavy combo raised
`AttributeError` and stopped the whole auto-combat.

### Fix (BaseWWTask override; PC/cloud behavior unchanged)

Override `mouse_down/mouse_up` in `BaseWWTask` (in the deploy manifest, inherited by all tasks),
so one fix covers every character's heavy combo:

- **Android**: `mouse_down()` resolves `-1,-1` to screen center (same as this class's `click()`
  handling for normal attack), presses via `nemu_impl.down(x,y)`; `mouse_up()` releases via
  `nemu_impl.up()`. If no nemu channel or the call fails, it degrades to a single `click()` so
  the combat loop never breaks on an exception.
- **PC / cloud**: when `is_adb()` is False, delegate straight to `super()` — behavior unchanged.

  coverage of 20+ character call sites)
- Regression: `TestAndroidDisconnect` 7, `TestAndroidTargetKey` 13, `TestAndroidCombatFix` 13,
  `TestCloudCombatFixes` 4 — all pass
