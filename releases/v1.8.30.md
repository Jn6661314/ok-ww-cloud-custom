# v1.8.30 · 手机投屏：修好「点开始没反应」和画面越来越卡，补齐斩杀/索拉指南/先约电台触点 / Phone mirroring: fix "won't start" and growing lag, add break / guidebook / battle-pass touch points

## 一、点了开始没反应，界面永远停在「等待游戏启动」

现场日志（同一秒、互相矛盾）：

```
14:46:29,975  手机投屏: 内核就绪, 画面端口 50086
14:46:29,978  手机投屏: 已连接 sidecar 127.0.0.1:50086
14:46:30,408  手机投屏: 解码分辨率 1920x864
14:46:30,420  手机投屏画面区: x=9 y=56 1901x808
14:46:33,707  ERROR 手机投屏: 投屏内核还没就绪, 请在手机上的 NectarLink 里点「允许」
14:46:35,709  ERROR（2 秒后又一条）……一直循环
```

**内核其实活着、画面也已经正常在收**（`link.json`、`sidecar.json` 都是 `{pid:34340, port:50086}`）。
问题在 `DeviceManager` 手里那个引擎对象的 `port` 是 `None`、`process` 也是 `None`——
它从没拉起过内核，却又不去接回磁盘上正在跑的那个，于是每 2 秒空等一次然后报错，
`start_device` 永远过不去，界面就卡在「等待游戏启动」。

现在发现「对象没持有端口」就先 `engine.start()` 一次：`start()` 会读 `link.json`，
端口还通就直接复用——**不需要在手机上重新点「允许」**。只有真的接不回来才报原因，
并且日志里会多一行 `引擎没持有端口(id=…)`，方便下次确认是不是两个引擎对象在打架。

## 二、画面延迟大，而且越用越滞后

同一帧被**解码了两遍**：预览窗口取一次、任务取一次，每次都是 NV12→BGR + 裁剪 + 放大到 1080 高
（1901×808 → 2540×1080，十几毫秒）。CPU 吃满 → 收帧线程抢不到 GIL → 内核侧发送队列越积越多
→ 画面越来越滞后。

- `do_get_frame()` 按 `frame_seq` **缓存解码结果**，一帧只解一次；
- `_read_message` 改用 `bytearray` + `recv_into`，省掉每帧 3~4MB 的重复拷贝；
- 预览缩放到窗口大小改用 `INTER_LINEAR`（缩小时比 `INTER_AREA` 快 2~3 倍）。

上一版已经做过的另一半：预览窗口不再自己开第二条 socket（内核原本给每个客户端都复制一份全帧），
而是复用任务那条抓屏通道，只在 `frame_seq` 变化时重绘，刷新间隔 33ms → 16ms。

## 三、键位触点：斩杀 / 索拉指南 / 先约电台

- 校准窗口现在把 **`f`（交互）**、**`f_break`（斩杀 / 谐振破坏）**、**`f2`（索拉指南）**
  分成三个**各自独立**的触点。别名（斩杀、fbreak、break）只会落到 `f_break`，**不会覆盖 `f`**——
  手游里捡东西和「谐振破坏」是两个按钮，混用会把人拉去交互。
- 新增 **`battle_pass`（先约电台）** 触点：这一项原本在 PC 上靠「按住 Alt 才显示右上角入口」，
  手游没有 Alt，只能点图标。投屏下 `_open_battle_pass` 先点校准过的触点，**不再发 `alt`**
  （发了什么也不会发生，只白等）。
- 校准窗口的状态行改成从 `CALIBRATION_KEYS` 生成，以后再加键不会漏报。

## 四、每日任务读不到活跃度

手游的活跃度是**一个独立的数字**（比如 `120`），不是 `x/100` 那种分式。旧代码只认分式，
所以在手机上永远读不到。现在：

- 先试分式，分母只接受 `100` 或 `200`（避免把任务行的 `0/1` 当成进度）；
- 再试纯数字（0~200），在多个候选里挑**离底部「活跃度」标签最近**的那个；
- 两条都读不到就标记为「未知」，**不冒充 0**，并跳过刷体力——以前会以为活跃度满了直接收工。

## 五、每日任务一直在按返回菜单

超宽画幅（2376×1080，约 2.2:1）下 `android_world` 的 ROI 是按 1920×1080 标定、又被独立拉伸的，
左上小地图框算出来落在 `x=49..247`，实际在 `x=186..383` —— 每帧都判「不在大世界」，
于是不停地按返回去找主界面，形成死循环。

- 新增**投屏专用判据**：不看亮度，看固定区域的白像素占比——左上小地图大世界 `0.011` / 面板 `0.269`，
  右下技能栏 `0.039` / `0.417`，再用底部 HUD 下限 `0.035` 排除纯深色的登录/过场画面；
- 顺手加了 **back 节流**：10 秒内超过 5 次就停发并告警一次，避免任何判定失误再变成无限按键风暴。

## 六、书明明开着，却报「找不到 boss 列表」

手机画面裁掉黑边后会等比放大到 1080 高（1901×808 → 2540×1080，**1.34 倍**），索拉指南左列的
类别图标跟着一起放大，而多尺度搜索的上限只有 `1.10` —— 永远差一档，书开着也匹配不上。

- `SCALES` 从 `0.40~1.10` 扩到 **`0.35~1.45`（12 档）**；
- 新增弱匹配下限 `FALLBACK_IOU = 0.38`：差一点也点进去（点错了上层会重试，比中断整条每日任务好）；
- 触屏端 `wait_book` 超时 3 秒 → **6 秒**（投屏多一层编码延迟，图标画全要时间）；
- `openF2Book` 现在把「书没打开」和「书开着但认不出类别」分开报，不再一律提示「确认 f2 是不是书的快捷键」。

## 七、默认码率删掉一个 0

`8000000` → **`800000`**（8 Mbps → 0.8 Mbps）。配置项默认值、说明文字、引擎构造参数的兜底全部同步。
码率只影响清晰度、不影响延迟；画面发糊就往上调，网络差就往下调。

## English summary

Everything here is about **phone mirroring (built-in engine)**.

**1. Clicking start did nothing.** The log showed the engine ready on port 50086 and frames decoding
normally, while `DeviceManager` logged "engine not ready" every two seconds. The engine object it held
had `port = None` and `process = None` — it had never started that engine and never re-attached the one
already running on disk, so `start_device()` could never pass. It now calls `engine.start()` first,
which reads `link.json` and reuses the live port **without asking the phone for permission again**.

**2. Growing lag.** The same frame was decoded twice (once for the preview, once for the task): NV12→BGR,
crop, then upscale to 1080 high — about ten milliseconds each. Decoding is now cached per `frame_seq`,
the socket reader uses `bytearray` + `recv_into` instead of re-copying 3–4 MB per frame, and the preview
scales with `INTER_LINEAR`.

**3. Touch points.** `f` (interact), `f_break` (resonance break) and `f2` (guidebook) are three
independent calibration points and aliases can no longer fall back to `f`. A new `battle_pass` point
covers the battle-pass entry, which on PC requires holding Alt — mobile has no Alt, and mirroring no
longer sends that keystroke at all.

**4. Daily activity points.** On mobile the activity value is a standalone number (e.g. `120`), not
`x/100`. The reader now accepts a fraction only with a `100`/`200` denominator, then falls back to a bare
number (0–200), preferring the candidate nearest the "activity" label. If neither is readable the value
is marked unknown instead of being reported as zero.

**5. The daily task kept pressing back.** On the 2376×1080 mirroring frame the world-detection ROIs
(calibrated for 1920×1080 and stretched independently) landed on the minimap box in the wrong place, so
every frame looked like "not in the open world" and the task hammered the back key. A mirroring-specific
check based on white-pixel ratios replaces it, plus a back-key throttle (more than 5 presses in 10 s stops
and warns once).

**6. "Cannot find the boss list" with the book open.** The phone frame is cropped and upscaled 1.34×, so
the left-column category icons are larger than any scale the template search tried (cap was 1.10×). The
scale range is now 0.35–1.45, a weak-match floor of 0.38 lets a near miss through, the touch-mode
`wait_book` timeout goes from 3 s to 6 s, and errors now distinguish "book not open" from "book open but
category not recognised".

**7. Default bitrate:** 8 Mbps → 0.8 Mbps.

**Tests:** 520 passing, with new coverage for every item above. No in-game verification was done for this
release, by prior agreement.
